# 项目目录与迁移说明

本次为架构第 15 章的目录整理阶段：建立目标位置与 CMake 入口，不进行业务代码迁移。各节点尚无 main.cpp，共用模块尚无具体 API，避免把占位程序视为已实现功能。旧工程按原入口独立构建。

| 现有位置 | 后续归属 / 处理 |
| --- | --- |
| AviatorRobot/、AviatorRobot_simple/ | 先保留；按职责拆到 aviator_core、manipulator 和确实共用的 common 模块 |
| pin_ik-main/ | 保留历史来源；核对与 third_party/pin_ik 的差异、路径引用及许可证后统一 |
| third_party/pin_ik/ | 新工程逆运动学依赖的目标位置，待依赖锁定和接入 |
| 根目录 xCoreSDK 目录及归档 | 保留；与 third_party 中 SDK 核对后统一，由 manipulator 接入 |
| urdf/、meshes/、Solidworks/ | 保留现有资源路径，待模型安装布局确定后迁移 |
| reference/ | 历史参考实现，排除在根工程构建之外 |
| examples/、tools/ | 保留既有示例与离线辅助工具；新运行节点统一放 nodes/ |

flight_gateway 合并 RS422 与 USB 摇杆输入，不新增 joystick_gateway。manipulator 统一双臂双手生命周期，仍分别维护 arm.* 与 hand.* 消息。运行监测、记录、曲线和回放均放入 nodes/。

后续顺序：冻结协议及配置，锁定并接入所需依赖，实现公共模块与总线，再逐节点迁移实现与有意义的测试，最后增加安装、systemd 和发布规则。旧文件的移动或去重应与引用修改、构建和功能验证同步进行。

本次未清理历史已跟踪的二进制与构建产物；新增忽略规则用于新根工程的 build/、用户预设和 MCAP 数据，不会自动取消历史文件的跟踪。
