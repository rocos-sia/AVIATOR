# 项目目录与迁移说明

当前已经将 `examples/AviatorRobot_simple` 的双臂控制能力迁移到两个运行节点，旧示例保留作历史对照。

| 来源 / 目标 | 当前职责 |
| --- | --- |
| nodes/aviator_core | 原 Aviator 业务流程、PIN-IK、碰撞规划、Ruckig、MoveWheel/ServoWheel、Demo 和交互入口；通过 ZMQ 执行 |
| nodes/manipulator | 双臂生命周期、Rokae 关节阻抗、MuJoCo 后端、窗口、本地窗口插值和 watchdog |
| common/protocol、transport、runtime | 既有公共通信能力；来源校验扩展了显式 local.task 授权 |
| common/motion | 双臂窗口、配置、服务信封和非实时客户端工具 |
| common/include/aviator | 两节点使用的设备/运动数据与接口；不会给纯通信 target 引入机器人链接依赖 |
| config/system.yaml、robot.yaml、grasp.json、posture.json | 新节点统一运行配置 |
| models/urdf、models/meshes、models/mjcf | 运动学统一使用 aviator.urdf；专用 aviator_collision.urdf/SRDF 保留简化碰撞几何，网格统一置于 models/meshes；仿真使用 models/mjcf/aviator.xml。原 models/control 中的重复模型已移除，旧示例资产保留在 examples/AviatorRobot_simple |
| third_party/RH56FTP | 灵巧手厂商资料、手册、示例、URDF 及现有示教器代码；rh56ftp_hand 复用其中的 Python 通信实现 |
| tests | 消息校验、跨进程仿真、实际轮盘运动与故障注入 |

构建仍从 AVIATOR 根 CMakeLists.txt 进入，两个节点不依赖 examples 构建选项。third_party 使用根目录统一依赖，不在节点内再复制第三方库。Core 不链接 xCore SDK；Manipulator 的 SDK 单独放共享库隔离其内嵌符号。

迁移保留用户已废除的 grasp/TCP 到位偏差判据。lock/unlock 使用一致的软件操作阶段；仿真保留 weld 物理连接，但不以偏差或抓握验证作为动作准入。独立测试可以检查实际轮盘跟踪，该断言不会加入运行控制流程。

`nodes/simulation` 是另外保留的仿真测试节点；同一总线不要同时启动它和 manipulator 作为机械臂反馈生产者。此次没有扩展真实手部驱动、视觉控制和全量记录系统。

新节点使用方法见 [Core](../nodes/aviator_core/README.md)、[Manipulator](../nodes/manipulator/README.md)，协议采用的能力见 [ZMQ 第 19 节](AVIATOR_ZMQ协议格式说明.md)。后续删除旧示例或去重应与其测试、路径和用户调用一起迁移，不在此次隐式删除。
