# AVIATOR 机器人系统故障编码规范

版本：V1.1 ICD 简化版（1127 状态语义补充）

更新日期：2026-11-27

依据：故障码表沿用 [ICD初稿-20261008.docx](ICD初稿-20261008.docx)；未启动、状态反馈异常及新增告警编码按 [【公开】ICD文件-1127.docx](【公开】ICD文件-1127.docx) 第 1.2、1.3 节及第 2 部分补充说明。

本规范按当前 ICD 整理，保留原有 50 个故障码并新增 6 个告警码，共 **8 个已分配类别、56 个故障码**。故障码占 **2 字节**，按 **无符号 uint16、小端模式**传输，CSNN 业务故障码的十进制编码范围为 **1000～9999**。具体码值和名称以本文第 4 节与 ICD 对应表为准，替代 V1.0 扩展码表。当前及历史故障编码不使用 `0xFFFF`，故障状态不新增未知值；本次新增告警统一使用现有 `0x30`。

本文仅规定故障编码与接口解释，不代表相应检测和上报功能已经实现。当前 RS422 协议修订为下行 **32 字节**、上行 **64 字节**、周期 **12.5 ms（80 Hz）**；原规范引用的 14/65 字节、20 ms 帧格式不再适用于本文。

1127 补充规定 `0xFE` 仅表示“未启动”，其余 Core 状态反馈异常按第 5.3 节归入上行 `ERROR`。这是接口目标行为；本次文档补充不表示网关代码已完成对应修改，也不新增 Core 故障联动或独立停机监控。

## 1. 编码规则

```text
故障码 = 类别 C × 1000 + 等级 S × 100 + 具体编号 NN
编码形式：CSNN
```

| 段 | 取值 | 含义 |
| --- | --- | --- |
| 千位 C | 1～9 | 类别字段允许范围；当前仅分配 1～8，9 类未分配。 |
| 百位 S | 0～3 | 0 警告；1 自恢复故障；2 需手动恢复故障；3 不可恢复故障。 |
| 后两位 NN | 01～98 | 具体故障；仅第 4 节列出的完整组合可以发送。 |

示例：`1203 = 1×1000 + 2×100 + 03`，表示**左机械臂、需手动恢复、过流保护**。

码值按十进制分配，不是十六进制分段、BCD 或 ASCII。接收后按整数运算拆分：

```text
C  = code / 1000
S  = (code / 100) % 10
NN = code % 100
```

`NN=00`、`NN=99`、等级位 4～9 及未列入码表的组合均不发送。原 V1.0 的 `x099/x199/x299/x399` 通用码和 9 类故障码不再使用；`9999` 也不表示未知故障。未映射的内部错误保留原始诊断，不能临时编造外部码或当作健康。

`0x0000` 表示当前无故障；在上一次故障字段中，表示本次网关运行期间尚无上一条故障记录，不表示设备全生命周期无故障。该值不按 CSNN 拆分。

当前及历史故障编码只发送 `0x0000` 或本文已分配业务故障码，不发送 `0xFFFF` 或未分配码。来自 Core 的当前故障字段缺失、类型错误、越界、非零值未映射，或 ERROR 状态却提供零故障码时，上报 `8212`（Core 诊断编码异常）；原始值及详细原因保留在本地诊断中，不截断、不伪装无故障。

| 2 | 右机械臂 | 2000～2399 | 右机械臂报错信息。 |
| 3 | 左灵巧手 | 3000～3399 | 左灵巧手报错信息。 |

## 3. 等级与故障状态

| 百位 | 等级 | 恢复含义 |
| ---: | --- | --- |
| 0 | 警告 | 提示异常或资源裕量不足。 |
| 1 | 自恢复故障 | 原因消除并确认恢复后，该故障可自动清除。 |
| 2 | 需手动恢复故障 | 原因消除后，仍需人工确认或错误复位。 |
| 3 | 不可恢复故障 | 不能通过普通业务复位继续本次运行，需检修或维护处置。 |

诊断清除不表示自动恢复操控，仍应按机器人状态机执行恢复流程。设备无法连接的条目按 ICD 编入 `x3xx`，不得自行降为自恢复故障。

1127 修订统一采用上行字节 21 已有取值，不新增故障状态。原等级表中的 `0x01/0x02/0x03/0x04` 对应修正为 `0x10/0x20/0x30/0x40`。

| 故障状态 | 含义 | 对应故障码等级 S |
| --- | --- | --- |
| `0x00` | 正常 | 当前故障码为 0 |
| `0x10` | 注意（警告） | 0 |
| `0x20` | 提示（自恢复） | 1 |
| `0x30` | 告警（需手动恢复） | 2 |
| `0x40` | 危险（不可恢复） | 3 |

本次新增 `7202～7206`、`8212` 的等级位均为 2，故障状态统一为 **`0x30`**。字节 21 不发送 `0xFF`，不定义“故障状态未知”。既有危险级故障仍按 `0x40` 上报，不因本次修订降级。

## 5. RS422 字段与小端示例

### 5.1 故障字段位置

上行帧共 64 字节，偏移从 0 开始。

| 偏移 | 长度 | 内容 |
| ---: | --- | --- |
| 10 | 1B | 机器人运行状态；1127 修订的未启动、ERROR 及急停解释见第 5.3 节。 |
| 12 | 1B | 应急手刹（光电 X1）：`X1=1 → 0x00` 未触发，`X1=0 → 0x01` 已触发，`0xFF` 表示输入无效或过期；详见第 5.6 节。 |
| 17～18 | 2B | 当前故障编码，17 为低字节、18 为高字节。 |
| 19～20 | 2B | 上一次已上报故障编码，19 为低字节、20 为高字节；按第 5.4 节在网关本次运行期间锁存。 |
| 21 | 1B | 故障状态，仅使用 `0x00/0x10/0x20/0x30/0x40`；本次新增项统一为 `0x30`。 |
| 26～29 | 4B | 机械臂实际关节角 FK 得到的滚转/俯仰位置反馈。 |
| 30～62 | 33B | 备用位，发送填零，参与帧校验。 |
| 63 | 1B | 帧校验和，字节 2～62（不含帧头）直接累加，取低 8 位；无帧尾。 |

1127 修订将历史字段明确为网关本次运行期间的上一条已上报故障，更新和清除规则见第 5.4 节；不声称该字段覆盖 Core 或设备的全部历史。

### 5.2 编解码

```text
低字节 = code & 0xFF
高字节 = (code >> 8) & 0xFF
code   = uint16(低字节) | (uint16(高字节) << 8)
```

| 十进制故障码 | 含义 | uint16 数值 | 线上字节顺序 |
| ---: | --- | --- | --- |
| 1203 | 左臂过流保护 | `0x04B3` | `B3 04` |
| 2203 | 右臂过流保护 | `0x089B` | `9B 08` |
| 3203 | 左手过流/堵转保护 | `0x0C83` | `83 0C` |
| 6302 | 应急手刹触发（不可恢复） | `0x189E` | `9E 18` |
| 7107 | ZMQ 总线链路中断 | `0x1BC3` | `C3 1B` |
| 7202 | Core 状态反馈超时 | `0x1C22` | `22 1C` |
| 8212 | Core 诊断编码异常 | `0x2014` | `14 20` |

例如当前故障为左臂过流 `1203`，上一次故障字段为右臂过流 `2203`，上行字节 17～20 应为 `B3 04 9B 08`。当前故障 `1203` 的等级位为 2，字节 21 填 `0x30`。

### 5.3 未启动与 ERROR 判定（1127 修订）

以下为上行字节 10 的接口语义，不新增 Core 内部状态：

| 线上值 | 名称 | 含义 |
| --- | --- | --- |
| `0xFE` | 未启动（`NOT_STARTED`） | 本次网关进程启动后，尚未建立有效 Core 状态反馈，且未发现来自预期 Core 的明确状态数据异常。 |
| `0x10` | 故障（`ERROR`） | Core 自身处于 ERROR，或网关检测到状态反馈异常、诊断编码异常。 |
| `0xFF` | 急停锁存（`EMERGENCY_STOP`） | 收到新鲜、有效的 Core 急停状态。 |

“未启动”适用于 Core 尚未启动、内部消息链路尚未建立或首个有效状态尚未到达；不能据此断定 Core 进程没有运行或机器人已经停止。从未收到 Core 状态时保持未启动，本次不新增启动等待期限，也不按运行期 100 ms 超时转为 ERROR。 未启动按正常启动等待处理：当前故障码为 `0x0000`，故障状态为 `0x00`；收到首个有效状态即可正常退出等待，不需要告警确认或错误复位。

收到首个有效、新鲜的 Core 状态后，立即按实际状态上报，`INIT`、`INITIALIZING` 等均不再归入未启动。一旦建立过有效反馈，本次网关运行期间不得因 Core 退出、重启或反馈中断退回未启动。网关进程重启后重新建立启动判定，可能再次短暂上报未启动。

| 情况 | 判定与上报规则 |
| --- | --- |
| 状态反馈超时 | 已建立有效反馈后，距最近一次有效接收达到 100 ms，或缓存状态的原始采样年龄达到 100 ms，上报 ERROR；重复发送缓存上行帧不延长有效期。 |
| Core 明确声明无效 | 来自预期 Core，且通过必要身份、顺序和时间校验的消息声明 `valid=false`，立即上报 ERROR；首次有效状态建立前亦适用。 |
| 状态内容异常 | 可归属预期 Core 的状态消息缺少必填字段、字段类型错误或状态名称无法映射，立即上报 ERROR；首次有效状态建立前亦适用。未知状态不得映射为未启动。 |
| 身份、顺序或时间校验失败 | 发布者或时钟域不符、序号重复或乱序、重启后时间戳倒退、样本过旧或超前的消息均拒绝，不刷新旧状态有效期。已有有效反馈时，旧状态到期上报 ERROR；仅收到被拒绝或无关来源消息，不得据此将启动等待直接判为 ERROR。 |
| 本地时间检查异常 | 已建立反馈后，本地时间回退或缓存时间关系异常，使状态有效性无法确认时，上报 ERROR。 |

诊断编码异常按 `8212` 上报 ERROR；不支持的运行状态按 `7205` 处理。网关应分别记录超时、明确无效、内容异常、状态不支持及身份/顺序/时间校验失败等诊断原因。上述规则针对 **Core 到网关的状态反馈**；飞控到网关的 RS422 输入断链不直接等同于状态反馈异常，仍通过相应通信状态、故障码及 Core 实际状态表达。

网关生成的 ERROR 是接口异常上报，**不等同于 Core 状态机已进入 ERROR，也不作为已停机、已执行保护或已完成故障复位的证据**。新鲜、有效的急停状态仍上报 `0xFF`；急停反馈失效后按反馈异常规则处理，此时上报 ERROR 不表示原急停已经解除。

### 5.4 明确故障编码与字段示例（1127 修订）

| 可确认的条件 | 当前故障码 | 故障状态 | 运行状态 |
| --- | ---: | --- | --- |
| 首个有效 Core 状态尚未建立，且无明确数据异常 | 0 | `0x00` | `0xFE` 未启动 |
| 已建立反馈，随后达到 100 ms 有效期上限 | 7202 | `0x30` | `0x10` ERROR |
| 通过必要校验的 Core 消息声明 `valid=false` | 7203 | `0x30` | `0x10` ERROR |
| 预期 Core 状态报文缺少必填状态字段或类型/结构错误 | 7204 | `0x30` | `0x10` ERROR |
| Core 状态名称合法可读，但不在支持的映射表中 | 7205 | `0x30` | `0x10` ERROR |
| 已建立反馈后，本地时间回退或缓存时间关系异常 | 7206 | `0x30` | `0x10` ERROR |
| Core 当前诊断字段缺失、类型错误、越界、非零值未映射，或 ERROR 无具体故障码 | 8212 | `0x30` | `0x10` ERROR；新鲜有效的急停状态仍优先上报 `0xFF` |

被拒绝的重复、乱序、身份不符或过旧/超前消息本身不立即生成 `7206`；它们不刷新有效期，已有反馈最终过期时按 `7202` 处理，具体拒绝原因留在本地日志。首次有效反馈建立前的无关消息不改变正常启动等待状态。

按“时间基准异常 → 状态无效 → 状态格式错误 → 状态值不支持 → 反馈超时”的顺序选择当前反馈诊断；内容类原因仅使用通过必要来源校验的消息。新鲜有效状态存在时，按其具体业务故障码上报；诊断不能按码表解析时使用 `8212`。状态反馈异常期间不把旧的 Core 故障当作当前新鲜诊断。

历史故障字段由网关维护：启动时为 `0x0000`，表示本次运行尚无上一条故障记录。当当前已上报故障码由非零值 A 切换为不同值（包括 0）时，将 A 存入历史字段；同码重复上报不覆盖历史。历史不因当前故障解除或普通错误复位而清零，网关重启后重新从 0 开始，不承诺跨进程持久化。历史中包含网关自身上报的明确诊断码，不再直接复制不可取得的 Core 历史字段。

| 场景 | 字节 10 | 字节 17～18 | 字节 19～20 | 字节 21 |
| --- | --- | --- | --- | --- |
| 本次启动首次上报，等待 Core 状态 | `FE` | `00 00`（当前无故障） | `00 00`（尚无上一条记录） | `00` |
| 启动后正常运行且无历史故障，首次反馈超时 | `10` | `22 1C`（7202） | `00 00`（尚无上一条记录） | `30` |
| 当前诊断编码异常 | `10`；急停时 `FF` | `14 20`（8212） | 保留上一条已上报故障 | `30` |

上表字节均为十六进制。字节 10 的 `0xFF` 仍表示急停；字节 21 不使用 `0xFF`。未启动属于正常启动等待，运行状态为 `0xFE`、当前故障码为 `0x0000`、故障状态为 `0x00`；不产生告警、不需要人工确认或错误复位，也不单凭等待时长认定 Core 启动失败。

### 5.5 恢复规则（1127 修订）

状态反馈恢复有效后，恢复上报 Core 实际运行状态；Core 仍处于 ERROR 时继续上报 ERROR。运行状态恢复与故障告警清除分开处理：新增故障均属等级 2，原因消除后仍须人工确认或错误复位，才能清除对应告警；原因未消除时不得清除。仅收到新鲜状态不得自动清除 `7202～7206` 或 `8212`，也不得自动发送复位、启动控制或运动指令。

告警尚未确认清除时继续保留对应故障码及 `0x30`；出现新的活动故障时先上报活动故障，待确认告警在本地保留，活动故障处理后按发生先后显示待确认项。人工确认只清除对应已消除原因的告警，不清空历史故障记录，也不代表 Core 接受复位或恢复运动。

本次修订不增加 Core 故障联动或独立停机监控。如果要求所有上行 ERROR 均触发实际停止，应另行定义控制与监控机制，不能仅靠替换上行状态码实现。人工确认入口及与原有错误复位操作的配合需在实现和联调中落实。

### 5.6 应急手刹光电输入（X1）

上行偏移 **12**（从 0 开始，即整帧第 **13** 个字节）表示逻辑触发状态，不直接传输原始电平：

| 光电 X1 | 上行手刹字节 | 含义 |
| --- | --- | --- |
| 有效、新鲜的 1 | `0x00` | 未触发 |
| 有效、新鲜的 0 | `0x01` | 已触发 |
| 尚无数据、无效、非法或原始采样达到 100 ms | `0xFF` | 当前手刹输入不可用 |

网关直接订阅 `photoelectric.state`，发布者默认 `aviator_photoelectric`、通道固定 X1；采集端保留原始电平（`invert: false`），网关转换一次，模拟器不再次取反。后退到位仍在偏移 11，不改变已有帧布局。

此处 `0xFF` 仅是手刹输入有效性标记，不是故障状态字段；偏移 21 仍不使用未知值。手刹反馈与 Core 急停锁存独立，X1 恢复为 1 不解除急停。本次只接入测量和显示，不新增 `6302` 故障触发规则，不把无效输入伪装为已触发，也不将物理手刹驱动确认与该光电输入混为一谈。

## 6. 版本切换与待确认项

V1.1 与 V1.0 存在同码不同义，发送端和接收端必须同时更新字典，不能混用。例如 `1204` 已由“电机过流保护”改为“关节位置超限”，`1301` 已由“驱动器或控制器损坏”改为“通信中断（设备无法连接）”。内部原厂错误需按当前码表显式映射，不直接截断或透传。

本版删除旧版扩展故障、通用兜底码、详细触发门限要求、复杂诊断聚合与恢复实现说明，保留 ICD 所需的编码规则、分类、等级和两字节传输方式；1127 修订在原 50 个故障码上新增 6 个明确告警码。后续新增故障应先更新 ICD，再同步本文件。

1127 修订新增 `7202～7206`、`8212`，共 8 类、56 个故障码，故障状态仍使用原有五个取值。收发双方须同步采用 `0xFE=未启动`、扩展后的 ERROR 语义及本次历史记录规则，不能混用旧版“`0xFE` 表示任意未知状态”或发送 `0xFFFF/故障状态0xFF` 的实现。应在网关、模拟器及监控界面完成适配和验证后切换；本次文档修改不构成实现完成或联调通过。

本次已明确无故障值 0、故障状态 `0x00/0x10/0x20/0x30/0x40`、新增告警原因、历史字段更新及重启行为。联调仍需落实 Core 多个业务故障同时存在时的选择规则、人工确认入口及错误复位衔接，验证告警清除不会自动恢复操控。
