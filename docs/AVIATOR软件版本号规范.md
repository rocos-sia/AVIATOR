# AVIATOR 软件版本号规范

版本：V1.1

日期：2026-10-19

状态：RS422 编码按 ICD 图片修订为高 8 位主版本、低 8 位小版本。

## 1. 适用范围

AVIATOR 完整发布版本继续使用 `vMAJOR.MINOR.PATCH`，例如 `v2.1.3`。RS422 软件版本字段占 2 字节，仅上报 **MAJOR.MINOR**：高 8 位为 MAJOR，低 8 位为 MINOR，按 **uint16 小端**发送。PATCH 保留在完整版本字符串、Git 标签和发布元数据中，不占线上位。

系统版本覆盖本次交付的 Core、Gateway、设备节点、运行脚本、随包依赖、模型和配置，不单独代表某个进程。线上版本不能区分同一 MAJOR.MINOR 的不同 PATCH；完整发布身份仍须核对完整版本和软件内容摘要。

本规范按 ICD 图片恢复 **8+8 位**定义，替代项目此前的 4+4+8 位编码。当前帧布局见 [RS422 通信协议规范](AVIATOR_RS422通信协议规范.md)，软件内容校验见 [软件校验码规范](AVIATOR软件校验码规范.md)。

## 2. 命名和递增规则

| 分量 | 名称 | 递增条件 | 示例 |
| --- | --- | --- | --- |
| MAJOR | 主版本 | 通信接口、命令含义、状态/故障语义或配置格式发生不兼容变化。 | `v1.3.5 → v2.0.0` |
| MINOR | 次版本（ICD 小版本） | 增加功能，保持已声明接口向后兼容。 | `v1.3.5 → v1.4.0` |
| PATCH | 修订号，仅保留于完整发布版本 | 向后兼容的缺陷修复、稳定性改进或交付内容修订。 | `v1.3.5 → v1.3.6` |

1. `v` 是显示名称和 Git 标签前缀；CMake 等机器可读版本使用 `2.1.3`，不带 `v`。三个分量均为非负十进制整数，不加前导零。ICD 示例 `2.01` 表示主版本 2、小版本 1，不是 CMake 版本字符串，也不是 BCD。
2. 增加主版本时，次版本和修订号归零；增加次版本时，修订号归零。按三个整数比较完整版本，不能按字符串排序。
3. `v0.x.y` 用于初始开发；正式稳定交付从 `v1.0.0` 开始。本规范不自动修改当前项目版本，普通编辑或构建不升级版本。
4. 正式版本发布后，已交付内容不可覆盖。程序、依赖、模型或纳入软件校验的配置改变时，分配新完整版本并重新计算校验值；完全相同的已发布文件可原样重新分发。
5. 兼容性以对外协议和声明的运行契约判断，不能仅按修改代码行数决定。改变控制含义或安全约束的参数调整需评估兼容性，不能一律视为 PATCH。
6. PATCH、Git 提交号、工具链、依赖版本和发布配置不压入低 8 位。不采用把 MINOR 与 PATCH 拼接、相加或截断的编码方式。

## 3. RS422 编码

### 3.1 位分配

| 位段 | 内容 | 允许范围 |
| --- | --- | --- |
| bit15～bit8 | MAJOR | 0～255 |
| bit7～bit0 | MINOR | 0～255 |

```text
version_u16 = (MAJOR << 8) | MINOR
MAJOR = (version_u16 >> 8) & 0xFF
MINOR = version_u16 & 0xFF
```

MAJOR 或 MINOR 超过 255 时，构建/发布检查必须失败，不截断、不回绕、不自动进位。PATCH 必须为非负整数；串口字段不限制 PATCH 为 8 位，也不能从串口版本恢复 PATCH。

### 3.2 字段位置与字节序

当前上行帧长度为 64 字节，偏移从 0 开始：

| 偏移 | 内容 |
| ---: | --- |
| 22 | MINOR，版本 uint16 的低字节。 |
| 23 | MAJOR，版本 uint16 的高字节。 |

| 完整软件版本 | ICD 主/小版本 | uint16 数值 | 线上字节 22～23 |
| --- | --- | --- | --- |
| `v2.1.0` | `2.01` | `0x0201` | `01 02` |
| `v2.1.3` | `2.01` | `0x0201` | `01 02` |
| `v1.0.3` | `1.00` | `0x0100` | `00 01` |
| `v1.2.15` | `1.02` | `0x0102` | `02 01` |
| `v255.255.0` | 主版本 255、小版本 255 | `0xFFFF` | `FF FF` |

`0xFFFF` 和 `0x0000` 均为合法线上版本，不保留为未知值。发布元数据缺失或校验失败时，不伪造版本；异常表达由独立诊断处理。

## 4. 正式版与测试版

正式交付只使用无后缀版本，例如 `v2.1.3`。开发/台架测试可使用预发布标签，Git 提交等另行记录；构建/发布工具仍要求规范的无后缀三段版本。

16 位字段不包含 PATCH 或预发布标识。因此不能仅凭线上版本断言完整发布一致，也不得占用合法版本位表达测试标志。显式台架测试身份必须在配置和界面中标明。

## 5. 版本来源与发布信息

根 [CMakeLists.txt](../CMakeLists.txt) 的 `project(AVIATOR VERSION ...)` 是唯一完整版本源。构建/发布步骤生成各程序版本显示、编码及机器可读发布信息，不为串口另设可独立漂移的版本常量。

发布目录中的 `release-version.json` 纳入软件内容校验，示例如下：

```json
{
  "product": "AVIATOR",
  "version": "2.1.3",
  "version_u16": 513,
  "release_profile": "hardware"
}
```

Gateway 启动时验证实际运行目录，**同时核对完整版本字符串与编码**，不能只比较 `version_u16`，否则不同 PATCH 会被误认。完整摘要与完整版本用于区分具体交付；16 位软件短码仍可能碰撞。系统其他组件的混装检测和门控按各自实现范围验收。

本文件中的示例版本不自动替代项目版本。生成流程见 [版本与校验码实现方案](AVIATOR版本与校验码实现方案.md)。

## 6. 编解码参考与验收

```python
import struct

def encode_version(major, minor):
    if any(type(v) is not int for v in (major, minor)):
        raise ValueError("版本分量必须为整数")
    if not (0 <= major <= 255 and 0 <= minor <= 255):
        raise ValueError("版本超出 8+8 位范围")
    return struct.pack("<H", (major << 8) | minor)

def decode_version(raw):
    value, = struct.unpack("<H", raw)
    return value >> 8, value & 255

assert encode_version(2, 1).hex(" ") == "01 02"
assert decode_version(bytes.fromhex("01 02")) == (2, 1)
assert encode_version(255, 255) == bytes.fromhex("ff ff")
```

验收覆盖最小/最大分量、非法分量拒绝、ICD 示例、小端字节序、PATCH 保留于元数据且不占线上位、正式版后缀检查、完整版本一致、偏移 22～23 及整帧校验。

旧 4+4+8 编码与当前 8+8 编码不得混用。帧中没有编码方案自描述位，两端需按部署版本同时切换；不根据码值猜测格式。旧发布元数据应由新构建重新生成并验证，不手工修改摘要或编码冒充一致。
