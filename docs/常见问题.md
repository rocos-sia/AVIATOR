# 常见问题

## Q：关闭终端后重新启动，提示“一键启动脚本已在运行。”，如何处理？

执行以下命令时，可能出现该提示：

```bash
AVIATOR_BIN="$PWD/build/release/bin" ./scripts/start_aviator.sh
```

**A：先检查上次启动的脚本和节点是否仍在运行，再停止残留进程并重新启动。不要直接删除锁文件。**

### 原因

[启动脚本](../scripts/start_aviator.sh) 使用 `flock` 防止重复启动，锁文件为：

```bash
${XDG_RUNTIME_DIR:-/tmp}/aviator-start-${UID}.lock
```

锁是否被占用取决于进程是否仍持有锁，而不是锁文件是否存在。当前脚本通过 `setsid` 启动各节点，节点可能继承用于加锁的文件描述符 `9`。如果直接关闭终端后未完成清理，即使启动脚本已经退出，残留节点仍可能占用锁。

本次排查发现：启动脚本已经退出，灵巧手节点仍持有锁，机械臂节点也未退出。因此，既要检查锁的占用者，也要检查其他残留节点。

### 处理步骤

1. 在新的终端中查看锁的占用者及相关进程：

   ```bash
   sudo fuser -v "${XDG_RUNTIME_DIR:-/tmp}/aviator-start-${UID}.lock"
   ps -eo user,pid,ppid,pgid,sid,args | grep -E '[s]tart_aviator.sh|[a]viator_bus|[m]anipulator|[r]h56ftp_node.py|[f]light_gateway|[a]viator_core_managed|nodes/[c]amera/main.py|[a]viator_monitor|[a]viator_logger|[s]imulation'
   ```

   根据命令路径和参数确认哪些进程属于上一次 AVIATOR 启动。`PID` 是进程号，`PGID` 是进程组号；机械臂节点由 `sudo` 启动，通常以 `root` 身份运行。每次启动的进程号都会变化，不能复用之前排查时的数值。

2. 确认设备可以停止后，优先正常退出旧启动脚本。

   如果原终端仍可用，按 **Ctrl+C** 并等待清理结束。如果脚本仍在运行但原终端不可用，对查询到的脚本 PID 发送 `TERM`，触发其清理逻辑：

   ```bash
   # 将 SCRIPT_PID 替换为实际的启动脚本 PID。
   kill -TERM SCRIPT_PID
   sleep 3
   ```

3. 如果脚本已退出，或仍有残留节点，对属于该次启动的节点进程组逐个发送 `TERM`：

   ```bash
   # 将 NODE_PGID 替换为 ps 输出中确认的节点 PGID，保留前面的负号。
   sudo kill -TERM -- -NODE_PGID
   sleep 3
   ```

   负号表示停止整个进程组，可以同时处理 `sudo` 及其启动的节点。只处理已确认属于上次启动的进程组，避免影响其他程序。

   再次执行第 1 步的检查。如果节点仍未退出，确认 PID、PGID 和设备状态后，再对相应残留进程组发送 `KILL`：

   ```bash
   # 仅在 TERM 无效时使用；KILL 不执行程序自身的退出清理。
   sudo kill -KILL -- -NODE_PGID
   ```

4. 确认 `fuser` 不再列出占用进程，并且旧节点已经退出后，在仓库根目录重新启动：

   ```bash
   AVIATOR_BIN="$PWD/build/release/bin" ./scripts/start_aviator.sh
   ```

### 注意事项

- 不要通过删除锁文件绕过检查。旧进程可能仍持有原文件的锁，删除后重新启动可能产生两套设备控制进程。
- 不要只停止占用锁的进程就立即重启；其他未持有锁的节点也可能残留并继续占用设备或端口。
- 正常退出时，在启动终端按 **Ctrl+C**，等待“正在停止本次启动的节点…”的清理过程结束，再关闭终端。
