# RH56FTP 握持负载调节设计

在现有模式 0 运动和逐指停滞保持基础上，增加有界的自动减载：确认稳定接触后写入一次 `-1`，持续监测电流、受力和温度；电流持续超限时，按实际位置逐指小幅松开，再对该手六路停止并观察；温度超限仍立即保护。调节失败通过无效的 `hand.state` 交给 Core 现有反馈保护处理。

仓库配置已开启自动减载。电流、受力和温度提供原始寄存器刻度的初始调试默认值，需按实际手柄验证；默认值不代表厂家的长期额定值。未加载配置且未显式启用时，程序保持关闭以兼容原有运动行为。本次只修改手节点、配置、文档及测试，不修改 Core、通信协议信封或 Modbus 后端。

## 协议依据和适用范围

仓库内 RH56E2 用户手册 §2.6.11 将角度 `-1` 定义为保持当前位置不动作；§2.6.20 的模式 0 在达到目标角度或力阈值时停止。两者均未保证电机断流。模式 1 是力闭环，模式 2 是持续电流保持，不作为本策略的工作模式。

电流、受力和温度配置统一采用原始寄存器整数刻度，直接比较反馈值，不做物理单位换算或归一化。最低接触/保持力 `min_force` 限定为与 `force` 指令相同的 0..3000；受力反馈仍保留协议的 -4000..4000 范围，以绝对值判断，不裁剪超出指令范围的读数。电流阈值使用反馈寄存器的 0..2000 范围，设备没有对应的电流设置指令。温度寄存器范围为 0..100，每刻度对应 1 ℃，初始停止阈值为 50。受力零点和接触方向需实机验证；电流小并不代表接触力小，机械自锁可以保留负载。

左右手五个弯曲通道参与自动松开；拇指侧摆只在保持阶段监测，不推断其松开方向。两手合计每次最多调整一个通道。设备自身错误码和无效位置等反馈异常仍检查；负载读数超出手册量程仅警告，不作为故障（见 2026-10-07 修正）。`hold_control` 的长期电流、最低保持力和温度阈值仅在该手完成抓握后应用，侧摆在此阶段持续超限也报告故障。

保持监测按每只手独立启用：至少一个弯曲通道已经保持，且五个弯曲通道均已保持或实际位置与请求位置的偏差不超过 `closing_motion_raw`。侧摆偏差不阻塞弯曲通道的减载；侧摆自身须实际到位或已因减载结束而停止后才应用长期阈值。其余弯曲手指尚在抓握运动时，已停住手指也不提前执行长期负载检查；全部仅到位但没有任何接触保持时，不宣称已抓住并进入减载。弯曲抓握/张开期间清零长期超限计时，重新张开会取消该手当前减载动作。

电流反馈按有符号 16 位解码后取绝对值参与负载检查，幅值超过手册范围 2000 时仅警告，不截断读数。厂家 ROS1 Modbus 示例 `getCURRENTCallback` 对 CURRENT 使用 `int16_t`，实机日志也出现 `65408 = 0xFF80 = -128`、`65367 = -169`、`65334 = -202`。Python 后端返回无符号字，手节点在反馈转换入口统一解码，同时兼容已解码的负值。原始字保留为 `current_register_raw`，日志同时保留有符号 `current_raw` 和幅值 `current_abs_raw`。

## 状态和判据

1. 闭合：保持现有角度及设备力阈值控制。存在闭合方向位置残差、有效新样本覆盖完整稳定窗口（现有默认 5 秒）、位置变化不超过容差，并且受力达到 `min_force`，才进入保持。该条件是接触证据，不设置 `grasp_verified=true`。
2. 闭合超时：持续闭合且有残差超过 `close_timeout_ms`（默认 30 秒，可设 60 秒）仍未进入保持，报告失败。30/60 秒是最长等待时间，不要求持续顶住到超时。抓握运动中使用设备模式 0 力保护，不使用长期电流、力和温度阈值触发故障。
3. 保持：只发一次 `-1`，重复闭合命令继续 ACK，不能覆盖保持状态。仅电流高于上限并持续 `overload_ms` 后申请减载；电流低于或等于上限乘 `recovery_ratio` 时清除超限计时。受力高不参与减载或恢复判断，温度达到阈值仍立即保护。低于最小握持力持续同样时间则报告握持不足。
4. 松开：正常目标取新鲜实测位置加 `release_step_raw`，限制在 0..1000 和首次保持位置加 `max_release_raw` 内。实际有松开位移且到达目标容差后向该手六路写 `-1`，包括侧摆及到位但未确认接触的弯曲通道；另一只手继续原动作。超过 `move_timeout_ms` 仍未到位，若位置仍在起点至目标的容差范围内，则先对该手六路请求 `-1` 并进入观察，打印单步未到位 WARNING；反向位移或超程超过容差仍失败。观察后若负载继续超限，重试目标取上次未到位目标与新鲜实测位置的较大值加步长，防止反复发送无效的小目标。负载恢复后清除重试目标。所有尝试计入原有步数、指令距离及总时间预算，不能无限重试。写失败不能提交保持/调节状态或更新命令 ACK。
5. 观察：停止后至少经过 `settle_ms` 的新反馈观察，再允许下一步；自动减载运动和观察期间不将电流峰值作为下一步依据，但设备错误和保持温度限制仍有效。观察后重新累计超限证据。累计步数和调节总时间也有上限，不无限松开。
6. 失败：锁存 `hold_control_error`，先请求六路 `-1`，发布 `valid=false`，Core 沿用现有反馈失效处理。故障只在重新连接/重启节点时清除。Core 停止命令后，watchdog 对全部已连接手发送安全张开姿态：拇指侧摆 `500`、其余五路 `1000`，避免侧摆到 `1000` 时与手柄干涉。启动、无效命令及退出路径共用此姿态，不因故障锁存而改为保持。watchdog 路径写失败会重试。保护性张开不清除故障锁存，不代表物理到位。

当前有效的明确张开目标优先于正常减载，清除该通道保持；故障锁存后普通位置命令不能恢复正常抓握，但允许保护性全张开。命令 watchdog、无效命令和退出路径执行全张开安全姿态时清除逐指保持及调节过程，保留故障锁存。反馈过期或读错误时不启动/继续减载，取消当前减载目标并请求 `-1`，清除连续观测证据；不使用重复旧样本累计时间。

### 2026-10-07 负载量程越界改为警告

13:22:35 左拇指弯曲在运动阶段反馈受力 `4117`、电流 `-28`、温度 `24`、设备错误码 `0`。旧实现仅因受力超过手册 `-4000..4000` 而锁存故障，随后指令超时进入安全张开。按用户要求，替换此策略及上述 10 月 6 日量程越界即故障的处理：电流超出 `-2000..2000`、受力超出 `-4000..4000`、温度超出 `0..100` 均只记录 `load_feedback_out_of_range` WARNING，不单独触发故障锁存或使 `hand.state.valid=false`。

保留原始反馈，不裁剪数值或改变手册量程定义。警告按手、通道、字段分别限频，文本每 10 秒、JSON 每秒；变化的读数也计入同类警告。运动阶段仍不应用长期负载阈值；进入保持监测后，原始读数仍用于电流减载、最低保持力和温度保护；受力上限已按下述修正移除。因此超量程电流或温度仍可能触发保持阶段的减载或保护，但原因是对应控制阈值或调节预算，而非量程检查。设备故障码、位置有效性、反馈读取检查、退出/故障安全张开均保留；配置数值不变。

### 2026-10-07 仅电流触发减载，结束后本手六路停止

移除 `force_limit` 参数、启动/故障日志中的力上限以及 `min_force` 与力恢复阈值的关联校验。自动减载只依据电流幅值及电流恢复回差，受力高不再触发减载或阻止恢复；`min_force` 继续用于接触确认和保持力不足检测。按用户确认，温度达到 `temperature_limit` 仍立即保护，不改为温度触发减载。设备模式 0 的 `force` 指令不变。

每次减载到位或单步超时转入观察时，向完成该步骤的手六路一次性写入 `-1`，包含拇指侧摆；另一只手继续原动作。重复旧目标不会重新启动侧摆和已经到位的弯曲通道。新侧摆目标、明确张开、指令超时和退出安全姿态仍生效；未确认接触的通道不会因该停止操作被标记为已握住。后续电流仍超限时，继续按原步数、位移和时间预算逐指减载。

六路停止仅在写入成功后提交状态并打印完成日志；写失败沿用故障锁存与安全张开路径，不确认命令或提交停止状态。停止后的侧摆仍检查电流和温度，但不自动松开。

## 配置

`config/rh56ftp_hand.yaml` 新增 `hold_control` 映射，启动时校验后加载。电气/受力阈值支持一个标量或六项数组，顺序为 AVIATOR 的拇指侧摆、拇指弯曲、食指、中指、无名指、小指；左右手共用，首版不增加每侧覆盖或运行时热更新。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| enabled | true（仓库配置） | 加载配置后启用；程序无配置时仍为 false |
| threshold | 10 | 保持位置偏移警告阈值，整数 0..1000；绝对偏移严格大于此值时警告，不影响抓握停滞/到位判据或控制动作 |
| current_limit | 100 | 六路电流反馈刻度上限，整数 0..2000 |
| min_force | 50 | 弯曲通道最低接触/保持力刻度，整数 0..3000；不作为过载减载依据 |
| temperature_limit | 50 | 六路温度反馈刻度阈值，整数 0..100，保持监测阶段达到即停止 |
| close_timeout_ms | 30000 | 闭合最长时间 |
| overload_ms | 1000 | 超限/握持不足确认时间 |
| recovery_ratio | 0.8 | 电流恢复阈值相对于 current_limit 的比例 |
| release_step_raw | 5 | 每步松开寄存器刻度，不是角度度数 |
| release_tolerance_raw | 2 | 松开到位容差，小于步长 |
| max_release_raw | 30 | 相对首次保持位置的最大松开刻度 |
| max_steps | 6 | 每次保持最多松开次数 |
| move_timeout_ms | 2000 | 单步到位期限 |
| settle_ms | 2000 | 到位停止后的观察时间 |
| adjust_timeout_ms | 60000 | 从第一次自动松开起的总调节期限 |

`force` 仍是写给设备的力保护阈值；软件 `force_limit` 已移除，旧配置须删除该项。稳定窗口及位置容差继续使用已有 `--closing-hold-ms`、`--closing-motion-raw`，避免重复配置。未知字段、布尔值冒充数字、非有限数、无效数组和不合理阈值关系均在建立设备连接前拒绝。

上述三个寄存器阈值省略时采用默认值，显式填写 `null` 或小数会被拒绝。旧字段 `current_limit_ma`、`force_limit_g`、`min_force_g`、`temperature_limit_c` 不再接受，需改为表中的名称。`min_force=0` 会取消最低接触力门槛，不建议在未验证接触检测时使用。`temperature_limit=0` 会在进入保持监测时立即停止。

## 实现和诊断

复用 `ClosingHold` 和命令线程中的 `_closing_targets`，增加逐指负载状态，不增加线程或阻塞等待。观测证据以反馈采样时间推进，动作期限使用主机单调时钟；现有读线程和发布频率不变。pending 状态在 Modbus 写入成功后提交，连续命令不能把已减载通道重新压回旧闭合目标。两手写入不具备事务性，启用调节时任何控制写失败都锁存故障，不从新的实测位置自动重试减载，避免部分写成功导致未计入预算的额外松开。

`hand.state` 增加顶层 `hold_control_error`，各手增加调节阶段、步数及目标；原有实际测量字段和 ACK 保持原语义。终端默认输出简洁中文，正常运动及稳定保持不周期打印，仅在启动配置、调节阶段变化、异常和反馈恢复时输出必要信息。`valid=false` 确保当前 Core 无需识别新增字段也会停止控制；Core 仍显示原来的反馈失效原因，具体减载错误读取手节点日志或新增字段。

连接时输出配置摘要，设备错误按位解码为中文并使用 ERROR 级别打印，减载动作使用 WARNING。文本模式相同原因的重复设备/I/O 错误每 10 秒最多提醒一次，并统计省略次数；新原因、反馈状态变化及恢复立即提示。启动参数 `--log-format json` 可启用完整诊断，包括 `configuration` 全部配置、失败前通道和测量值、阈值、计时器、步骤预算、命令上下文及 Modbus 调用栈。JSON 模式保留异常期间的周期性健康汇总和每秒重复错误限频，但正常保持不触发汇总。

## 验证

单元测试使用假时钟和 Modbus 假设备验证：稳定接触、闭合超时、持续超限及回差、逐指调节、实际位置目标、松开到位和观察、旧命令不恢复闭合、明确张开、低握持力、过温/设备错误、反馈中断、单步/总量/次数/时间边界、写失败不提交状态、配置加载和禁用兼容性。

运行 `python -m unittest discover -s nodes/rh56ftp_hand -p 'test_rh56ftp_node.py'`。测试包含原始刻度配置校验、错误日志上下文与限频、独立本地 ZMQ 总线集成，以及日志电流补码、负向电流超限和真正越界值的回归验证。测试使用假设备，实机复测需另行执行。

实机验收需读回模式 0，确认 `-1` 后电流；标定接触力和松开步长，记录六路电流/受力/温度、位置和调节事件；覆盖超过此前约一小时的驾驶盘运动工况，验证温升和滑移。温度滞后于电流，策略不因短期温度未下降而连续松开。该机制不处理原有读线程轮询长间隔问题。
