## 改动核验

- boot_id 缓存：短栈命中 [7, 41] → [0, 34]。源码已缓存 boot_id；采样中 local_clock_id 仍可能出现（还需拼接字符串/读取 hostname），不出现也不能证明成本为零。
- GPU 扫描缓存：短栈命中 [16, 57] → [0, 42]。源码增加发现间隔及客户端缓存；结合 Monitor CPU 与该路径变化判断，不以短栈比例单独计算收益。
- 消费式 JSON 编码：短栈命中 [4, 41] → [4, 34]。源码保留 const 路径并新增右值路径；encode 仍有验证和 dump 成本，不能要求函数消失。
- 解析工作区复用：短栈命中 [16, 57] → [15, 42]。源码增加有界 thread_local ParseWorkspace，减少重复键检查的临时分配；解析和严格验证仍然保留。
- 单末端帧 FK：短栈命中 [4, 113] → [2, 213]。源码改为 updateFramePlacement；FK 主体仍需要执行，比较规划时序与运动学类别成本。

短栈命中非调用次数或 CPU%，样本不足、栈截断均会影响结果。多项改动同时部署，不能拆分收益。
