## 2. 按优先级执行的修改任务

### A1 Core：缓存 boot_id，去掉高频文件读取

函数：`local_clock_id()`。位置：`common/runtime.cpp:37；common/motion.cpp:86；nodes/aviator_core/RemoteLink.cpp:576`。

**当前多做了什么：** 发送消息和校验接收消息都会调用时钟域标识函数；一个系统启动周期内不变的 boot_id 被反复打开、读取、关闭。

**具体怎么改：** 先只把 boot_id 缓存为进程内线程安全的 static const std::string，保留 gethostname 及现有错误处理。若要缓存完整 clock_id，先明确运行期 hostname/命名空间变化契约。保持返回值格式一致；new_session_id() 读取的随机 uuid 绝不能一并缓存。

**希望改善什么：** 消除确定的重复文件 I/O；CPU 节省比例待实测。

**如何验收：** 多线程重复调用值一致；读取失败行为符合现有约定；同负载下确认 boot_id 文件打开次数从每条消息降为每进程初始化一次，复测 Core CPU 和消息新鲜度。

**风险与边界：** 低；先确认进程运行期间不切换到不同 boot_id 来源的挂载命名空间。

**证据：** Core 短栈 7/41 个样本包含 local_clock_id；源码显示每次都创建 ifstream 读取 boot_id。CPU 平坦表也出现 read_id。
短栈数字为“包含该函数的样本数 / 本阶段总样本数”；不同任务卡可覆盖同一样本，不能相加，也不是 CPU 百分比。

```cpp
// 示意，尚未修改主程序
static const std::string boot = read_id("/proc/sys/kernel/random/boot_id");
return std::string(hostname).substr(0, 80) + "-" + boot;
```

### A2 Monitor：缩小 GPU 统计扫描范围

函数：`intelGpuSample() / gpuPercent()`。位置：`nodes/aviator_monitor/system.cpp:60；nodes/aviator_monitor/main.cpp:404`。

**当前多做了什么：** 为了显示 GPU 使用率，周期性打开大量与 GPU 无关的文件；与控制算法无关，也占用了 Monitor 的 CPU。

**具体怎么改：** 维护已发现的 DRM 客户端候选缓存：已知客户端按原周期读取，完整发现降低到可配置的 2–5 秒；识别 PID starttime、FD 复用、退出与权限错误，按设备/client-id 去重。解析时先检查 drm- 前缀，再解析需要的字段，减少对无关行创建 istringstream。页面显示 GPU 样本时间和发现延迟。

**希望改善什么：** 减少监控自身的扫描和解析开销；不改变控制周期。

**如何验收：** 运行 GPU 客户端启动/退出、PID/FD 复用、dup/fork 去重和权限受限用例；对照原实现的 GPU 趋势；保持 arm/hand 新鲜度刷新不变。记录扫描文件数、资源线程 CPU 与扫描时长。

**风险与边界：** 低至中；降低发现频率会延迟发现新 GPU 客户端，需显式展示，不伪装为实时数值。

**证据：** Monitor 短栈 16/57 个样本包含 gpuPercent（含其内联路径）；源码每轮枚举 /proc/PID/fdinfo 并对文件逐行构建字符串流。资源采样周期约 1 秒。
短栈数字为“包含该函数的样本数 / 本阶段总样本数”；不同任务卡可覆盖同一样本，不能相加，也不是 CPU 百分比。

### A3 公共消息发送：消除可避免的 JSON 深拷贝

函数：`encode() → publishMessage()`。位置：`common/protocol.cpp:205；common/motion.cpp:100`。

**当前多做了什么：** 调用者刚构造好消息，encode 又复制整个 body，增加分配、拷贝和析构；但不能把全部 malloc 样本都归因于这一行。

**具体怎么改：** 保留 const Message& 接口；新增消费右值的发送/编码路径，仅在发送后不再使用 Message 的调用点 move body。把编码实现抽为可接收已拥有 JSON 的内部函数，保留头字段冲突、NaN/Inf、整数范围、包长和业务规则检查。先迁移 Core 的一次性发布对象，再逐项扩展。

**希望改善什么：** 降低一次性消息的分配/复制量；不能承诺 Core CPU 下降 18%。

**如何验收：** 新旧路径编码后 JSON 语义、header/body、错误输入拒绝行为一致；验证失败时参数所有权约定；使用代表性 arm.state/flight.state/命令包做离线吞吐与分配次数对照，再用相同负载复测。

**风险与边界：** 中；错误移动仍被使用的消息会改变逻辑，不能全局替换为 std::move。

**证据：** Core 60 秒样本中：E 核事件 malloc 9.64%、_int_malloc 8.43%、_int_free 6.04%；P 核事件 _int_free 18.02%、malloc 12.45%。这是 Self 占比，不可跨 PMU 相加。短栈 4/41 个样本可见 encode；源码 auto json = message.body 明确执行整份复制。
短栈数字为“包含该函数的样本数 / 本阶段总样本数”；不同任务卡可覆盖同一样本，不能相加，也不是 CPU 百分比。

```cpp
// 现有热点候选
auto json = message.body; // 完整复制
// 建议：仅消费式接口中转移所有权
auto json = std::move(message.body); // 需新增接口与调用点审查
```

### A4 Monitor 收包：减少 JSON DOM 与重复键检查的临时分配

函数：`State::ingest() → decode()`。位置：`nodes/aviator_monitor/monitor.cpp:124；common/protocol.cpp:172`。

**当前多做了什么：** 每包生成通用 JSON DOM；每层对象创建并销毁 unordered_set 做重复键检测，随后又递归检查数值和结构。代码已经是一次 parse，不应错误建议“去掉第二次 parse”。

**具体怎么改：** 先用真实消息离线统计各 topic 的字节数/包率与解析成本，再优化最重主题。可试验保留严格校验的 SAX 路径：一遍验证整个输入，同时仅构建监控摘要必需字段；仍保存原始 payload 供详情查看。若先做小改动，复用有界解析工作区，核验是否真正减少分配，不直接删除重复键或深度检查。

**希望改善什么：** 目标是减少 DOM 和临时容器成本；需要离线 A/B 证明再决定是否上线。

**如何验收：** 逐包比对现有 decode 的接受/拒绝、gaps/duplicates、publisher/session、时间戳与详情展示；覆盖重复键、深层对象、NaN/Inf、错误 msg_type、异常大包。验证显示新鲜度不退化。

**风险与边界：** 中至高；这是较大改造，先完成 A1/A2/A3；不靠丢弃告警或放宽校验省 CPU。

**证据：** Monitor 短栈 19/57 个样本可见 ingest，16/57 个可见 decode。平坦表 scan_string 在 E/P 核事件分别为 7.99% / 3.27%；重复键回调也被采到。
短栈数字为“包含该函数的样本数 / 本阶段总样本数”；不同任务卡可覆盖同一样本，不能相加，也不是 CPU 百分比。

### A5 Manipulator FK：仅更新实际需要的末端帧

函数：`PinIkKinematics::solveFk()`。位置：`nodes/aviator_core/Kinematics_pin_ik.cpp:76；nodes/aviator_core/ServoPlanner.cpp:206`。

**当前多做了什么：** forwardKinematics 已更新关节变换；随后遍历全部 frames，而当前函数只返回一个 tip 的位姿。

**具体怎么改：** 核实 data_ 的全部使用者不依赖此前刷新所有 oMf 后，将 updateFramePlacements(model,data) 改为 updateFramePlacement(model,data,tip)。保持 forwardKinematics 和几何残差检查。仓库所带 Pinocchio 已提供单帧更新实现；不要通过降低 FK/校验频率来替代这项改动。

**希望改善什么：** 减少多余 frame 变换计算；样本太少，无法保证明显 CPU 收益。

**如何验收：** 对左右臂限位内随机姿态、边界姿态及实际轨迹，对比位置/旋转误差；覆盖 solveFk → jointDerivatives 的连续调用；运行几何残差与控制回归，比较规划时长分布。

**风险与边界：** 中；共享工作区隐含依赖需先审查。

**证据：** Manipulator 60 秒 P 核事件 solveFk Self 为 4.19%，只有 2 个命中，不能视作精确份额。短栈 4/113 个样本出现 solveFk，并可见 checkGeometry 调用。源码更新全部 frames 后只读取 tip_[i]。
短栈数字为“包含该函数的样本数 / 本阶段总样本数”；不同任务卡可覆盖同一样本，不能相加，也不是 CPU 百分比。

```cpp
// 建议替换全帧更新，仅供后续实现审查
out = pinocchio::updateFramePlacement(model_[i], *data_[i], tip_[i]);
```

### A6 Manipulator 求导：为 Newton 修正提供只算速度的路径

函数：`ServoPlanner::endpoint() → PinIkKinematics::jointDerivatives()`。位置：`nodes/aviator_core/ServoPlanner.cpp:87；nodes/aviator_core/Kinematics_pin_ik.cpp:86`。

**当前多做了什么：** 用于修正位置误差的 Newton 步骤需要 J 的加权逆作用于误差，不一定需要完整加速度计算；最终轨迹输出仍需要完整求导。

**具体怎么改：** 新增使用同一加权 Jacobian/COD、同一速度残差检查的速度专用求解器，仅供 Newton 内层；最终轨迹点继续完整计算 dq/ddq。先确定原加速度残差检查在 Newton 阶段的故障检测契约，不能未经论证删除。不要改收敛阈值、8/120 次上限或控制频率。

**希望改善什么：** 可能减少每个 Newton 步骤中的冗余导数运算，收益和安全等价性都需验证。

**如何验收：** 比较迭代次数、收敛结果、分支连续性、奇异附近错误行为；完整轨迹保持速度/加速度/jerk 和轮姿残差约束；离线证明后再做硬件回归。

**风险与边界：** 高；改变数值路径与失败判定，放在前面低风险工作之后。

**证据：** 短栈 14/113 个样本包含 jointDerivatives。源码 Newton 内层传入零加速度，求出 dq/ddq 后只用 dq 更新 q；函数仍计算 dJ、lambda、redundant 与 ddq。
短栈数字为“包含该函数的样本数 / 本阶段总样本数”；不同任务卡可覆盖同一样本，不能相加，也不是 CPU 百分比。
