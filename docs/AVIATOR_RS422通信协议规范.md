# AVIATOR 飞控计算机与操纵系统 RS422 通信协议规范

修订日期：2026-10-11。

本文按 [ICD初稿-20261008.docx](ICD初稿-20261008.docx) 的当前 9/29 字节布局整理，并纳入已确认的 [软件版本号规范](AVIATOR软件版本号规范.md) 与 [软件校验码规范](AVIATOR软件校验码规范.md)。旧 14/65 字节布局及更早的 REQUEST/REPLY/CONTROL/STATUS 布局不再作为本文的当前接口。目录中的同名旧 Word 协议为历史方案，不是本文的同步副本。

当前两项软件信息均占 2 字节：版本使用 **4+4+8 位、uint16 小端**；软件校验码使用 **发布清单 SHA-256 的前 16 位、uint16 小端**。本文是接口规范，不表示串口运行实现或发布校验流水线已经接入。

## 1. 接口与周期

| 项目 | 定义 |
| --- | --- |
| 物理接口 | RS422，全双工。 |
| 波特率 | 115200 bit/s。 |
| UART 与流控 | 沿用既有约定：8N1，无软件/硬件流控。 |
| 周期 | 12.5 ms，80 Hz。 |
| 飞控→操纵系统 | 固定 9 字节。 |
| 操纵系统→飞控 | 固定 29 字节。 |
| 帧头 | 顺序发送 `EB 90`。 |
| 帧尾 | 仅上行有 `ED 03`，先 ED 后 03。 |
| 帧校验 | 校验字节之前全部字节累加，取反加 1，结果取低 8 位。 |

所有偏移从帧头第一个字节开始，以 0 为基准。帧没有额外 LEN、TYPE、事务 ID、时间戳或独立应答消息。

## 2. 下行帧 9 字节

```text
EB 90 | 帧计数器[1] | 状态指令[1] | 滚转指令[2] | 俯仰指令[2] | 帧校验[1]
 0..1       2             3            4..5          6..7          8
```

| 偏移 | 长度 | 字段 | 定义 |
| ---: | --- | --- | --- |
| 0～1 | 2B | 帧头 | `EB 90`。 |
| 2 | 1B | 帧计数器 | 0～255 循环计数。 |
| 3 | 1B | 状态切换指令 | 见第 2.1 节。ICD 要求连续发 10 拍，连续 5 拍后执行。 |
| 4～5 | 2B | 驾驶盘滚转指令 | -50°～50° 对应 -100%～100%，百分比分辨率 0.1。 |
| 6～7 | 2B | 驾驶盘俯仰指令 | 0～170 mm 对应 -100%～100%，百分比分辨率 0.1。 |
| 8 | 1B | 帧校验和 | 字节 0～7 累加补码。 |

ICD 将位置指令字段命名为“指令回绕”；其下行实际方向为飞控发给操纵系统。上行另有回绕字段，不将名称解释为相反传输方向。

### 2.1 状态切换指令

| 编码 | ICD 含义 | 内部操作对应 |
| --- | --- | --- |
| `0x00` | 无效 | 不发起新操作。 |
| `0x10` | 待机 | `ENTER_STANDBY`。 |
| `0x20` | 准备，抓握和随动 | `GRASP_WHEEL`。 |
| `0x30` | 控制 | `START_CONTROL`。 |
| `0x40` | 退出控制，回到准备 | `EXIT_CONTROL`。 |
| `0x50` | 释放，回到待机 | `LEAVE_WHEEL`。 |
| `0x60` | 错误复位 | `RESET_ERROR`。 |

六操作仍须由 Core 状态机守卫判定；指令回绕不等于动作已完成。“连续 5 拍”的有效帧认定、计数中断/重置、主备合并及第 6～10 拍不得重复执行的具体规则需联调冻结；不能看到每一帧就重启一次耗时任务。

## 4. 数值解释与反馈范围

已明确 uint16 小端的字段是：两个故障码、软件版本和软件校验码。其他两字节位置字段的有符号表示、字节序、缩放及无效值仍须明确，不能由帧尾顺序推导。

指令采用以下物理范围与百分比对应关系：

```text
P_roll  = roll_deg / 50 × 100
P_pitch = (pitch_mm - 85) / 85 × 100
```

其中 0° 滚转、85 mm 俯仰分别对应 0%。指令范围为 ±100%，分辨率写为 0.1；若约定每编码单位为 0.1 个百分点，则指令量化范围为 -1000～1000，具体有符号与舍入方式仍需冻结。

当前 ICD 将反馈物理范围扩大为滚转 ±52°、俯仰 -5～175 mm，但反馈信号说明仍写 ±100%，两者的缩放关系需要确认。此前方案沿用指令比例时对应 ±104% 和约 ±105.88235%；若按扩展范围重新归一化则比例不同。本文保留该差异为待确认项，不将任何一种解释当作本次已批准的变更。

回绕字段应取已定义接纳阶段的指令，不冒充实测位置。测量来源、缺失/过期、越界、端点舍入及无效值须在联调前冻结。

## 5. 故障字段

采用 [AVIATOR 故障编码规范](AVIATOR故障编码规范.md) V1.1 的 **8 类、50 个故障码**，按十进制 `CSNN` 编排，uint16 小端。未分配的 9 类、通用 x099/x199/x299/x399 和旧扩展故障不再使用。

故障状态在 ICD 中有两套值：上行偏移 21 使用正常 `0x00`、注意 `0x10`、提示 `0x20`、告警 `0x30`、危险 `0x40`；第 3 部分等级表使用 `0x01/0x02/0x03/0x04`。该冲突尚未确认，本次不擅自选择其中一套。

无故障 0、历史故障锁存更新/清除规则、多故障选择及故障状态表示单条还是整体异常，按故障规范的待确认项处理，不继续套用旧版自行扩展的轮询或历史持久化规则。

## 6. 软件版本

软件采用 `vMAJOR.MINOR.PATCH`。线上 bit15～12 为 MAJOR（0～15），bit11～8 为 MINOR（0～15），bit7～0 为 PATCH（0～255）。

```text
version_u16 = (MAJOR << 12) | (MINOR << 8) | PATCH
frame[22] = version_u16 & 0xFF
frame[23] = (version_u16 >> 8) & 0xFF
```

例如 `v1.0.3 → 0x1003 → 03 10`，`v1.2.15 → 0x120F → 0F 12`。不采用旧高 8 位主版本/低 8 位小版本定义，也不采用 BCD。超范围拒绝发布；正式运行不使用无法在线区分的预发布后缀。

详细命名、递增、构建来源及兼容切换要求见 [软件版本号规范](AVIATOR软件版本号规范.md)。

## 7. 软件校验码

对最终发布文件逐项计算 SHA-256，生成规范化 `SHA256SUMS`，再对该清单文件计算完整系统摘要。完整 64 字符摘要用于验收；上行仅发送其最左 4 个十六进制字符对应的 uint16，低字节在前。

```text
release_digest = SHA256(SHA256SUMS 文件字节).hexdigest()
checksum_u16 = int(release_digest[:4], 16)
frame[24] = checksum_u16 & 0xFF
frame[25] = (checksum_u16 >> 8) & 0xFF
```

例如摘要以 `abcd…` 开头，短码为 `0xABCD`，线上字节为 `CD AB`；这不是固定常量。摘要以 `ba78…` 开头则发送 `78 BA`，不直接复制原始摘要的前两字节。

短码可能碰撞，不代替完整摘要或数字签名。启动时验证实际部署文件，成功后缓存并周期上报，不能仅读取预置短码冒充文件校验。计算范围、清单格式和工具见 [软件校验码规范](AVIATOR软件校验码规范.md)。

## 8. 帧校验与示例

```text
frame_checksum = (-sum(frame[0:checksum_offset])) & 0xFF
下行 checksum_offset = 8
上行 checksum_offset = 26
接收：sum(frame[0:checksum_offset+1]) & 0xFF == 0
```

版本和软件短码属于帧内容，都参与帧校验；帧尾不参与。软件 SHA-256 校验与逐帧累加校验相互独立。

以下仅为布局和算法测试，不是可下发的真实业务帧。零占位不代表未定义测量有效；`abc` 的哈希仅用于验证短码截取和字节序，不是软件发布摘要。

```python
import hashlib
import struct

def seal(prefix, trailer=b""):
    return bytes(prefix) + bytes([(-sum(prefix)) & 0xff]) + trailer

down = bytearray(8)
down[0:2] = bytes.fromhex("eb 90")
down_frame = seal(down)
assert down_frame.hex(" ") == "eb 90 00 00 00 00 00 00 85"

up = bytearray(26)
up[0:2] = bytes.fromhex("eb 90")
struct.pack_into("<H", up, 22, (1 << 12) | 3)  # v1.0.3
digest = hashlib.sha256(b"abc").hexdigest()    # 算法测试向量
struct.pack_into("<H", up, 24, int(digest[:4], 16))
up_frame = seal(up, bytes.fromhex("ed 03"))
assert len(up_frame) == 29
assert up_frame[22:26].hex(" ") == "03 10 78 ba"
assert up_frame[26] == 0x40
assert up_frame[27:] == bytes.fromhex("ed 03")
assert sum(up_frame[:27]) & 0xff == 0
```

## 9. 联调边界

按 115200 bit/s、8N1、80 Hz 估算，下行占用 9×80×10=7200 bit/s（6.25%），上行占用 29×80×10=23200 bit/s（约 20.14%）；全双工两个方向分别计算。

已确认：帧长和字段位置按当前 ICD；版本 4+4+8 位、小端；SHA-256 清单完整摘要和前 16 位短码、小端。验收必须检查边界值、端序、帧校验及两端发布字典一致，不能用旧 65 字节测试向量代替。

其余仍需确认：位置字段编码与反馈归一化、缺失值、故障状态字冲突、RELEASING 上行值、连续指令执行细则、回绕时点、主备拓扑与关联/超时/切换、故障选择与历史锁存，以及版本/内容校验失败时的线上异常表达。此次版本号和软件校验码确认不自动解决这些独立问题。
