# AVIATOR 飞控计算机与操纵系统 RS422 通信协议规范

修订日期：2026-10-19。

本文以 [ICD初稿-20261008.docx](ICD初稿-20261008.docx) 的业务字段为基础，按本次备用位和帧校验位置修订为 **下行 32 字节、上行 64 字节**，UART、帧校验和版本字段按本次提供的《ICD文件-1017 (1).docx》图片同步，配套 [软件版本号规范](AVIATOR软件版本号规范.md) 与 [软件校验码规范](AVIATOR软件校验码规范.md)。旧 9/29、14/65 字节布局及更早的 REQUEST/REPLY/CONTROL/STATUS 布局不再作为本文的当前接口。目录中的同名旧 Word 协议为历史方案，不是本文的同步副本。

当前两项软件信息均占 2 字节：版本使用 **高 8 位主版本、低 8 位小版本、uint16 小端**；软件校验码使用 **发布清单 SHA-256 的前 16 位、uint16 小端**。`flight_gateway` 已实现第 10 节的双路台架配置；它补齐当前 ICD 尚未冻结的规则，不代表原 ICD 已完成接口方审批。

## 1. 接口与周期

| 项目 | 定义 |
| --- | --- |
| 物理接口 | RS422，全双工。 |
| 波特率 | 115200 bit/s。 |
| UART 与流控 | 8E1：8 位数据、偶校验、1 位停止位，每 UART 字共 11 位；无软件/硬件流控。 |
| 周期 | 12.5 ms，80 Hz。 |
| 飞控→操纵系统 | 固定 32 字节。 |
| 操纵系统→飞控 | 固定 64 字节。 |
| 帧头 | 顺序发送 `EB 90`。 |
| 帧尾 | 上下行均无帧尾；校验字节为帧的最后一个字节。 |
| 帧校验 | 不含同步字（偏移 0～1）及校验字节本身，其余字节直接累加，保留低 8 位。 |

所有偏移从帧头第一个字节开始，以 0 为基准。帧没有额外 LEN、TYPE、事务 ID、时间戳或独立应答消息。

## 2. 下行帧 32 字节

```text
EB 90 | 帧计数器[1] | 状态指令[1] | 滚转指令[2] | 俯仰指令[2] | 备用位[23] | 帧校验[1]
 0..1       2             3            4..5          6..7          8..30         31
```

| 偏移 | 长度 | 字段 | 定义 |
| ---: | --- | --- | --- |
| 0～1 | 2B | 帧头 | `EB 90`。 |
| 2 | 1B | 帧计数器 | 0～255 循环计数。 |
| 3 | 1B | 状态切换指令 | 见第 2.1 节。ICD 要求连续发 10 拍，连续 5 拍后执行。 |
| 4～5 | 2B | 驾驶盘滚转指令 | -50°～50° 对应 -100%～100%，百分比分辨率 0.1。 |
| 6～7 | 2B | 驾驶盘俯仰指令 | 0～170 mm 对应 -100%～100%，百分比分辨率 0.1。 |
| 8～30 | 23B | 备用位 | 发送填零；接收忽略业务含义，但参与帧校验。 |
| 31 | 1B | 帧校验和 | 字节 2～30 累加，保留低 8 位。 |

ICD 将位置指令字段命名为“指令回绕”；其下行实际方向为飞控发给操纵系统。上行另有回绕字段，不将名称解释为相反传输方向。

### 2.1 状态切换指令

| 编码 | ICD 含义 | 内部操作对应 |
| --- | --- | --- |
| `0x00` | 无效 | 不发起新操作。 |
| `0x10` | 待机 | `ENTER_STANDBY`。 |
| `0x20` | 准备，抓握和随动 | `GRASP_WHEEL`。 |
| `0x30` | 控制 | `START_CONTROL`。 |
| `0x40` | 退出控制，回到准备 | `EXIT_CONTROL`。 |
| `0x50` | 释放，回到待机 | `LEAVE_WHEEL`。 |
| `0x60` | 错误复位 | `RESET_ERROR`。 |

六操作仍须由 Core 状态机守卫判定；指令回绕不等于动作已完成。“连续 5 拍”的有效帧认定、计数中断/重置、主备合并及第 6～10 拍不得重复执行的具体规则需联调冻结；不能看到每一帧就重启一次耗时任务。

## 3. 上行帧 64 字节

```text
EB 90 | 帧计数器[1] | 主备[1] | 通信状态[1] | 状态指令回绕[1]
      | 滚转回绕[2] | 俯仰回绕[2] | 运行状态[1] | 后退到位[1] | 手刹触发[1]
      | 滚转反馈[2] | 俯仰反馈[2] | 当前故障[2] | 历史故障[2] | 故障状态[1]
      | 软件版本[2] | 软件校验码[2] | 备用位[37] | 帧校验[1]
```

| 偏移 | 长度 | 字段 | 定义 |
| ---: | --- | --- | --- |
| 0～1 | 2B | 帧头 | `EB 90`。 |
| 2 | 1B | 帧计数器 | 0～255。 |
| 3 | 1B | 主备指令 | `0x00` 主通道，`0x01` 备通道。 |
| 4 | 1B | 接收飞控通信状态 | b0 主通道、b1 备通道；0 正常、1 故障。其余位未定义。 |
| 5 | 1B | 状态切换指令回绕 | 与下行偏移 3 的枚举相同。 |
| 6～7 | 2B | 滚转指令回绕 | 与下行滚转指令对应。 |
| 8～9 | 2B | 俯仰指令回绕 | 与下行俯仰指令对应。 |
| 10 | 1B | 机器人运行状态 | 见第 3.1 节。 |
| 11 | 1B | 后部锁止机构状态，后退是否到位 | `0x00` 未到位，`0x01` 到位。 |
| 12 | 1B | 驾驶员应急手刹触发状态 | `0x00` 未触发，`0x01` 触发。 |
| 13～14 | 2B | 滚转实际位置反馈 | 物理范围 -52°～52°；百分比解释见第 4 节。 |
| 15～16 | 2B | 俯仰实际位置反馈 | 物理范围 -5～175 mm；百分比解释见第 4 节。 |
| 17～18 | 2B | 当前故障码 | uint16 小端，见故障编码规范。 |
| 19～20 | 2B | 上一次故障码 | uint16 小端，ICD 标注故障锁存。 |
| 21 | 1B | 故障状态 | ICD 两处数值有冲突，见第 5 节。 |
| 22～23 | 2B | 软件版本 | 8+8 位主/小版本，uint16 小端，见第 6 节。 |
| 24～25 | 2B | 软件校验码 | 发布清单 SHA-256 前 16 位，uint16 小端，见第 7 节。 |
| 26～62 | 37B | 备用位 | 发送填零；接收忽略业务含义，但参与帧校验。 |
| 63 | 1B | 帧校验和 | 字节 2～62 累加，保留低 8 位。 |

本帧不再包含旧版独立抓握指令回绕、速度限幅/速度反馈、双臂末端数组、相机检测状态、其他关节/力/电流等槽位，不得沿用旧偏移填充。

## 4. 数值解释与反馈范围

已明确 uint16 小端的字段是：两个故障码、软件版本和软件校验码。其他两字节位置字段的有符号表示、字节序、缩放及无效值仍须明确，不能仅由字段长度推导。

指令采用以下物理范围与百分比对应关系：

```text
P_roll  = roll_deg / 50 × 100
P_pitch = (pitch_mm - 85) / 85 × 100
```

其中 0° 滚转、85 mm 俯仰分别对应 0%。指令范围为 ±100%，分辨率写为 0.1；若约定每编码单位为 0.1 个百分点，则指令量化范围为 -1000～1000，具体有符号与舍入方式仍需冻结。

当前 ICD 将反馈物理范围扩大为滚转 ±52°、俯仰 -5～175 mm，但反馈信号说明仍写 ±100%，两者的缩放关系需要确认。此前方案沿用指令比例时对应 ±104% 和约 ±105.88235%；若按扩展范围重新归一化则比例不同。本文保留该差异为待确认项，不将任何一种解释当作本次已批准的变更。

回绕字段应取已定义接纳阶段的指令，不冒充实测位置。测量来源、缺失/过期、越界、端点舍入及无效值须在联调前冻结。

## 5. 故障字段

采用 [AVIATOR 故障编码规范](AVIATOR故障编码规范.md) V1.1 的 **8 类、50 个故障码**，按十进制 `CSNN` 编排，uint16 小端。未分配的 9 类、通用 x099/x199/x299/x399 和旧扩展故障不再使用。

故障状态在 ICD 中有两套值：上行偏移 21 使用正常 `0x00`、注意 `0x10`、提示 `0x20`、告警 `0x30`、危险 `0x40`；第 3 部分等级表使用 `0x01/0x02/0x03/0x04`。基础 ICD 的冲突仍待接口方统一；第 10 节台架配置显式选择上行帧表的 `0x10～0x40`。

无故障 0、历史故障锁存更新/清除规则、多故障选择及故障状态表示单条还是整体异常，按故障规范的待确认项处理，不继续套用旧版自行扩展的轮询或历史持久化规则。

## 6. 软件版本

完整发布版本采用 `vMAJOR.MINOR.PATCH`；线上仅传主版本 MAJOR 和小版本 MINOR，各占 8 位、范围 0～255。PATCH 保留在完整发布元数据中，不占线上位；不同 PATCH 可能具有相同线上版本。

```text
version_u16 = (MAJOR << 8) | MINOR
frame[22] = MINOR
frame[23] = MAJOR
```

ICD 示例 `2.01 → 0x0201 → 01 02`，对应完整版本 `v2.1.0`（或相同主/次版本的其他 PATCH）。这不是 BCD，不再采用 4+4+8 位编码。MAJOR/MINOR 超范围拒绝构建/发布；启动时同时核对完整版本字符串和线上编码，不能仅比较 16 位版本认定发布一致。

详细命名、递增、构建来源及兼容切换要求见 [软件版本号规范](AVIATOR软件版本号规范.md)。

## 7. 软件校验码

对最终发布文件逐项计算 SHA-256，生成规范化 `SHA256SUMS`，再对该清单文件计算完整系统摘要。完整 64 字符摘要用于验收；上行仅发送其最左 4 个十六进制字符对应的 uint16，低字节在前。

```text
release_digest = SHA256(SHA256SUMS 文件字节).hexdigest()
checksum_u16 = int(release_digest[:4], 16)
frame[24] = checksum_u16 & 0xFF
frame[25] = (checksum_u16 >> 8) & 0xFF
```

例如摘要以 `abcd…` 开头，短码为 `0xABCD`，线上字节为 `CD AB`；这不是固定常量。摘要以 `ba78…` 开头则发送 `78 BA`，不直接复制原始摘要的前两字节。

短码可能碰撞，不代替完整摘要或数字签名。启动时验证实际部署文件，成功后缓存并周期上报，不能仅读取预置短码冒充文件校验。计算范围、清单格式和工具见 [软件校验码规范](AVIATOR软件校验码规范.md)。

## 8. 帧校验与示例

```text
frame_checksum = sum(frame[2:checksum_offset]) & 0xFF
下行 checksum_offset = 31
上行 checksum_offset = 63
接收：frame[checksum_offset] == (sum(frame[2:checksum_offset]) & 0xFF)
```

帧头 `EB 90` 与校验字节自身不参与累加；帧计数器、业务字段（含版本和软件短码）及全部备用位参与帧校验，上下行均无帧尾。不取反、不加 1、不取补码。接收端不因备用位非零而拒绝校验正确的帧，也不将备用位解释为业务字段。软件 SHA-256 校验与逐帧累加校验相互独立。

以下仅为布局和算法测试，不是可下发的真实业务帧。零占位不代表未定义测量有效；`abc` 的哈希仅用于验证短码截取和字节序，不是软件发布摘要。

```python
import hashlib
import struct

def seal(prefix):
    return bytes(prefix) + bytes([sum(prefix[2:]) & 0xff])

down = bytearray(31)  # 业务字段及备用位均以零初始化
down[0:2] = bytes.fromhex("eb 90")
down_frame = seal(down)
assert len(down_frame) == 32
assert down_frame == bytes.fromhex("eb 90") + bytes(29) + bytes([0x00])
assert down_frame[31] == sum(down_frame[2:31]) & 0xff

up = bytearray(63)  # 包括偏移 26～62 的 37 字节备用位
up[0:2] = bytes.fromhex("eb 90")
struct.pack_into("<H", up, 22, (2 << 8) | 1)  # ICD 2.01，完整发布版本示例 v2.1.0
digest = hashlib.sha256(b"abc").hexdigest()    # 算法测试向量
struct.pack_into("<H", up, 24, int(digest[:4], 16))
up_frame = seal(up)
assert len(up_frame) == 64
assert up_frame[22:26].hex(" ") == "01 02 78 ba"
assert up_frame[26:63] == bytes(37)
assert up_frame[63] == 0x35
assert up_frame[63] == sum(up_frame[2:63]) & 0xff
```

## 9. 联调边界

按 115200 bit/s、8E1（每字节 11 bit）、80 Hz 估算，下行占用 32×80×11=28160 bit/s（约 24.44%），上行占用 64×80×11=56320 bit/s（约 48.89%）；全双工两个方向分别计算。

已确认：帧长、备用位和校验位置按本文本次修订，既有业务字段偏移保持不变；版本 8+8 位、小端；SHA-256 清单完整摘要和前 16 位短码、小端。验收必须检查边界值、端序、帧校验及两端发布字典一致，不能用旧 9/29 或 14/65 字节测试向量代替。

其余仍需确认：位置字段编码与反馈归一化、缺失值、故障状态字冲突、RELEASING 上行值、连续指令执行细则、回绕时点、主备拓扑与关联/超时/切换、故障选择与历史锁存，以及版本/内容校验失败时的线上异常表达。此次版本号和软件校验码确认不自动解决这些独立问题。


## 10. 双工控机台架实现配置 `aviator-bench-v1`

本节是双工控机联调用的明确补充，两端必须配置 `rs422.profile: aviator-bench-v1`。使用上文 32/64 字节布局；保留该 profile 名称用于台架配置，但不兼容旧 9/29 字节实现，也不兼容此前 8N1、含帧头累加补码及 4+4+8 版本编码实现，两端程序必须配套更新，不自动探测或兼容旧帧。当前 ICD Word 不作为本次修订的同步副本。它不等同于已批准的正式飞控接口。运行、接线和部署步骤见 [flight_gateway README](../nodes/flight_gateway/README.md)。

### 10.1 数值和无效表示

- 所有位置和回绕字段使用 **int16 小端补码**，1 编码单位为 **0.1 个百分点**；命令范围 `-1000～1000`。浮点转整数采用四舍五入，恰好半单位时远离零。
- 反馈沿用指令比例，滚转允许 `±1040`，俯仰物理端点量化约为 `±1059`。禁止将扩大后的物理行程重新归一化为 ±100%。
- 位置无效为 `0x8000`（线上 `00 80`）；不将无效位置当成零。
- `RELEASING` 使用 `0x14`，未知运行状态为 `0xFF`。
- 正常故障状态 `0x00`，四级故障状态 `0x10/0x20/0x30/0x40`；无故障码 `0x0000`。未知、未映射故障码 `0xFFFF`，未知故障状态 `0xFF`。这些都是台架哨兵，不增加已分配业务故障码。
- 后退到位、手刹状态无效均为 `0xFF`；正常取值仍为 0/1。
- 主备字段表示机器人当前选中的下行通道：0=A、1=B、`0xFF`=无可选通道。两路上行报告同一选择。
- 机器人内部坐标采用 `angle_rad=-roll_percent/100×50°`、`displacement_m=(pitch_mm-170)/1000`。保持既有手柄方向；接真实飞控前确认物理安装方向。

### 10.2 双路与时效

模拟器每 12.5 ms 向两路发同一计数、同一内容的下行帧。机器人两路独立解析，默认 A 优先；首次选择和重新连接需连续有效帧，默认 10 帧。通道恢复观察和操作空闲确认分别进行，连接就绪后再按操作键。选中通道过期且另一路恢复条件成立时切换，恢复的 A 不抢回。接收有效期默认 50 ms，可配置 25～100 ms；计数必须向前，回绕 255→0 有效，同计数和反向帧不续期。超过有效期重新建立计数基准。

同计数的两路内容不一致时撤销输入。切路目标差大于 `switch_max_step`（默认 100，即 10 个百分点）时也撤销输入。冲突/跳变恢复至少需要 100 ms 的无效窗口和 10 个连续空闲、无冲突周期；Core 对短暂失效保持原状态，持续失效或输入租约超时进入 ERROR，须显式复位到 READY 后恢复。这里是主备策略，不是双路投票，也不能由两个通道推断哪个值正确。

输入重新发布时保留串口接收时间，不以 ZMQ 发送时间续期；两路失效时立即发布 `valid=false`。8 位计数器没有远端时戳和重启标识，不能证明数据的原始生成时刻或可靠识别每一次远端重启。主循环延迟跳过周期，不补发旧帧。

### 10.3 状态操作

每次按钮按下沿产生 10 拍指令，随后至少 10 拍 `0x00`。长按不重复发送操作列。发送中或空闲隔离期内的新操作不排队，提示操作员稍后重新按键。

网关启动、切路、计数中断后需先见 10 拍连续 `0x00`，再对同一非零状态码连续 5 拍确认，并仅派发一次 Core 服务请求。两路副本不叠加计数，积压的一批帧不当作多个实时确认周期。操作派发后，无论接受、拒绝、未发送或响应超时，都必须重新经过空闲序列，不能靠第 6～10 拍重试。

上行状态回绕表示网关已经通过 5 拍确认并尝试派发的最新操作，保持到下一次操作或输入失效；不等同于 Core 接受或执行完成。位置回绕来自当前选中的有效命令。上行运行状态表示 Core 状态；内部服务结果仅在本机日志/服务记录中可见，不额外生成串口应答帧。

### 10.4 上行数据质量与软件身份

机器人两路独立以 80 Hz 发送上行；Core 连续目标和状态保持既有 50 Hz。重复发送快照不改变测量时效。Core 摘要过期 100 ms 后，状态和故障发送未知哨兵。实测位置必须来自带 `valid`、`sample_mono_us` 的 `wheel_measurement`；`wheel_reference` 永远不当作实测反馈。设备未提供测量时发送无效位置。

后退/手刹仅使用新鲜 `discrete_inputs` 硬件输入；当前 Managed Core 未接这些硬件，默认发送未知，不将 `software_lock`、`brake_requested` 或 `brake_confirmed=false` 替代真实传感器。已有 Core 通用错误 28673 无对应 ICD 语义，发送 `0xFFFF`，不可截断或伪造健康。若 Core 当前故障明确为 0、存在链路超时，按 A 优先上报 7101/7102；Core 非零/未知故障优先。历史字段仅采用 Core 导出的历史，不把网关链路瞬态混入其中。

启动时调用既有发布工具验证实际运行目录，校验成功后缓存软件身份。`release_root` 必须包含当前运行程序；完整版本字符串与线上编码都必须与编译版本一致。显式 `allow_test_identity: true` 仅在全部发布元数据缺失时允许既有 `0x9CA1` 台架短码；任何已有元数据验证失败都退出，不回退测试码。该开关不把测试软件认证为正式发布。

模拟器默认要求手柄在线；掉线停止两路下行发送。显式 `require_joystick: false` 时允许聚焦键盘备用，无手柄且失焦即停发，不沿用本机模式的 5 分钟保持。串口、手柄和程序恢复不自动重发上一操作。
