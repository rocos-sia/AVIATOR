# AVIATOR 项目构建说明

## 统一构建系统

本项目使用根目录的 CMakeLists.txt 统一管理整个项目的构建，包括第三方依赖和示例程序。

## Linux + VS Code 开发（推荐）

从仓库根目录打开 VS Code。安装/启用 `llvm-vs-code-extensions.vscode-clangd`、
`ms-vscode.cmake-tools` 和 `ms-vscode.cpptools`；C/C++ 扩展保留 GDB 调试功能，
其 IntelliSense 已在工作区禁用。需要 GCC/G++、CMake >= 3.22、Ninja、GDB、
clangd、clang-format 和 clang-tidy。项目代码采用 C++20；第三方库保留自己的标准与构建设置。

```bash
cmake --preset debug
cmake --build --preset debug

cmake --preset release
cmake --build --preset release
```

新 presets 使用 `/usr/bin/gcc`、`/usr/bin/g++` 和 Ninja，分别生成 `build/debug`
和 `build/release`。旧 `linux-debug`、`linux-release`、`simulation`、`replay` presets
及原有 `build/` 构建方式继续保留；不要在同一构建目录切换生成器。
每个新 preset 使用两个构建任务，第三方子项目也各自使用两个任务；首次完整构建会编译依赖。

Ubuntu 22.04 可通过统一脚本安装 apt 依赖及开发工具：

```bash
./scripts/install_dependencies.sh --dry-run  # 预览
./scripts/install_dependencies.sh            # 安装，按需调用 sudo
```

脚本同时安装 `libnlopt-dev` 和 `libnlopt-cxx-dev`，后者提供 PIN-IK 所需的 `nlopt.hpp`。
系统 NLopt C++ 开发包已确认安装；本次 Debug/Release 配置及 Debug 第三方构建已切回
系统依赖，不再依赖之前的 `build/dev-deps` 临时前缀。更多选项见
[scripts/README.md](../scripts/README.md)。

VS Code 中执行 **CMake: Select Configure Preset**，选择 `debug`，然后配置和构建。
`Ctrl+Shift+B` 也可配置并构建 Debug。clangd 始终通过
`--compile-commands-dir=${workspaceFolder}/build/debug` 读取 Debug 编译数据库，
即使 CMake Tools 切换为 Release，索引仍使用 Debug。这里需要显式指定：数据库在
`build/debug/`，而原 `build/` 还可能有另一份旧数据库。无需复制数据库或手填 includePath。
`--query-driver=/usr/bin/gcc,/usr/bin/g++` 让 clangd 查询实际编译器的系统头文件路径，
避免本机 LLVM 14 误选不完整的 GCC 12 安装而找不到 GCC 11 的标准库。
修改编译器时应同时更新 preset 和 query-driver 白名单。

CMake 配置后即可生成 `compile_commands.json`，但首次完整构建完成后才会有全部
第三方安装头文件。C/C++ 保存时由 clangd 按 `.clang-format` 格式化；clangd 内置的
clang-tidy 使用 `.clang-tidy` 检查，普通警告不阻止构建，不自动修复源码。
独立 clang-format/clang-tidy 工具与 clangd 尽量保持相同主版本。用户设置中的
`clangd.path` 可能使 VS Code 与终端使用不同版本；本次保留该设置。独立 clang-tidy
不读取 clangd 的 query-driver 参数；在存在不完整 GCC 安装的环境中，需要根据
`g++ -E -x c++ - -v </dev/null` 输出额外传入实际系统头文件路径，或修复工具链安装。
VS Code 内置检查已由上述 query-driver 设置处理。

F5 前在“运行和调试”选择 `GDB: ... (Debug)`。已配置真实目标 `aviator`、`simulation`、
`aviator_bus`、`flight_gateway`、`aviator_logger`、`aviator_monitor`，启动前会配置和构建
Debug，使用 `/usr/bin/gdb`。`aviator` 使用现有 MuJoCo 配置并关闭窗口；`simulation`
默认关闭窗口和相机。其他节点使用程序默认参数，可在 launch 配置中按需修改 `args`。
第三方 ExternalProject 继续使用 Release 编译，因此这些库的调试符号可能不完整。

可从根目录检查 clangd（修改文件名即可检查其他翻译单元）：

```bash
clangd --check=common/transport.cpp --compile-commands-dir=build/debug \
  --query-driver=/usr/bin/gcc,/usr/bin/g++ --clang-tidy
```

如果跳转仍异常，先确认 clangd 扩展已启动，在 Output → clangd 查看加载的数据库和
错误，然后执行 **clangd: Restart language server**，等待后台索引完成。没有被根 CMake
纳入构建的独立 examples/tools 不保证能从此数据库获得精确参数，需要用各自的 CMake
生成数据库并在独立工作区配置。不要用递归 includePath 掩盖缺失的编译信息。

参考：[clangd 项目配置](https://clangd.llvm.org/config)、
[CMake presets](https://cmake.org/cmake/help/v3.22/manual/cmake-presets.7.html)。

## 快速开始

### 从根目录构建整个项目

```bash
# 配置
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release

# 编译（推荐使用多线程）
cmake --build build -j4

# 运行测试
ctest --test-dir build --output-on-failure

# 安装
cmake --install build --prefix ./dist
```

## 仅构建 common 通信库

通信模块可独立于机器人、仿真和 SDK 依赖构建：

```bash
# Ubuntu 22.04 开发依赖；cppzmq 使用仓库固定的 4.11.0 头文件。
sudo apt-get install libzmq3-dev nlohmann-json3-dev libyaml-cpp-dev
cmake -S . -B build/communication \
    -DAVIATOR_COMMUNICATION_ONLY=ON \
    -DCMAKE_BUILD_TYPE=Debug
cmake --build build/communication --parallel
ctest --test-dir build/communication --output-on-failure
```

此选项跳过机器人依赖与 examples，生成 `aviator_protocol`、`aviator_transport`、`aviator_runtime`、`aviator_recording` 库，以及 `aviator_bus`、`flight_gateway`、`aviator_logger` 和 `aviator_monitor` 可执行程序及通信/记录测试。Logger 的当前支持范围见 [节点说明](../nodes/aviator_logger/README.md)。默认完整构建也需要上述通信依赖。`BUILD_TESTING=OFF` 可关闭测试。

非系统安装的依赖通过 `CMAKE_PREFIX_PATH` 指定；必要时分别指定 `AVIATOR_ZMQ_INCLUDE_DIR` 和 `AVIATOR_ZMQ_LIBRARY`。CMake 不自动联网下载依赖。已验证 libzmq 4.3.4、cppzmq 4.11.0、nlohmann/json 3.10.5；发布部署需固定实际依赖版本。

公共接口与线程/校验边界见 [common 使用说明](../common/README.md)。安装会复制四个公共库与头文件，使用安装头文件的工程仍需提供 libzmq、cppzmq 和 nlohmann/json 开发依赖。

## 构建选项

### 示例程序

```bash
# 禁用所有示例
cmake -S . -B build -DAVIATOR_BUILD_EXAMPLES=OFF

# 禁用特定示例
cmake -S . -B build -DAVIATOR_BUILD_EXAMPLE_SIMPLE=OFF
```

### 第三方库

```bash
# 禁用机器人库（Coal, Pinocchio, PIN-IK）
cmake -S . -B build -DAVIATOR_BUILD_ROBOTICS_LIBS=OFF

# 禁用 MuJoCo 仿真
cmake -S . -B build -DAVIATOR_BUILD_MUJOCO=OFF

# 禁用 xCoreSDK（Rokae 机器人）
cmake -S . -B build -DAVIATOR_BUILD_XCORE_SDK=OFF

# 禁用 GLFW 查看器
cmake -S . -B build -DAVIATOR_BUILD_VIEWER=OFF
```

### 组合示例

```bash
# 仅构建核心库和节点，不构建示例
cmake -S . -B build -DAVIATOR_BUILD_EXAMPLES=OFF

# 构建仿真版本（不包含真机支持）
cmake -S . -B build -DAVIATOR_BUILD_XCORE_SDK=OFF

# 构建真机版本（不包含仿真）
cmake -S . -B build -DAVIATOR_BUILD_MUJOCO=OFF -DAVIATOR_BUILD_VIEWER=OFF

# 最小构建（仅核心，无示例）
cmake -S . -B build \
    -DAVIATOR_BUILD_EXAMPLES=OFF \
    -DAVIATOR_BUILD_MUJOCO=OFF \
    -DAVIATOR_BUILD_XCORE_SDK=OFF
```

## AviatorRobot_simple 示例

### 从根目录构建（推荐）

```bash
cd /path/to/AVIATOR
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4

# 运行
./build/bin/aviator --demo --headless
```

### 示例的构建选项

在根目录构建时，`AviatorRobot_simple` 的选项会自动继承父项目的设置：

- `AVIATOR_WITH_SIMULATION` 继承自 `AVIATOR_BUILD_MUJOCO`
- `AVIATOR_WITH_ROKAE` 继承自 `AVIATOR_BUILD_XCORE_SDK`
- `AVIATOR_WITH_VIEWER` 继承自 `AVIATOR_BUILD_VIEWER`

也可以单独覆盖示例的选项：

```bash
cmake -S . -B build \
    -DAVIATOR_BUILD_MUJOCO=ON \
    -DAVIATOR_WITH_SIMULATION=OFF  # 示例不使用仿真
```

## 常见问题

### 1. 如何只构建 AviatorRobot_simple？

从根目录构建，禁用其他组件：

```bash
cmake -S . -B build -DAVIATOR_BUILD_EXAMPLES=ON
cmake --build build --target aviator -j4
```

### 2. 构建失败：找不到系统依赖

确保已安装所有系统依赖：

```bash
./scripts/install_dependencies.sh
```

### 3. 如何加速构建？

- 增加并行编译任务：`cmake --build build -j8`
- 减少第三方库的编译任务：`-DAVIATOR_DEPENDENCY_JOBS=1`
- 禁用不需要的组件

### 4. 如何清理重新构建？

```bash
rm -rf build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j4
```

### 5. 旧版本如何迁移？

旧版 `AviatorRobot_simple` 可以独立构建的方式已不推荐。请使用根目录统一构建。

如果需要单独维护示例，可以：
1. 复制整个 `third_party/` 目录
2. 复制 `cmake/ThirdPartyDependencies.cmake`
3. 在示例的 CMakeLists.txt 中 include 该文件

## 开发建议

- 在根目录使用 `CMAKE_EXPORT_COMPILE_COMMANDS=ON`（已默认启用）生成 `compile_commands.json`
- IDE 应该打开根目录作为项目根
- 使用 CMake Presets（参考 `CMakePresets.json`）

Web 监控启动：`./build/communication/bin/aviator_monitor`，浏览器访问 `http://127.0.0.1:8081`。页面嵌入程序，无额外 GUI 或前端构建依赖，详见 [监控说明](../nodes/aviator_monitor/README.md)。

## 双臂 ZMQ 节点

新运行入口为 aviator_core 与 manipulator，从根工程构建，关闭 examples 不影响这两个节点：

```bash
cmake -S . -B build
cmake --build build --target aviator_bus aviator_core manipulator -j3

# 分别在三个终端运行
./build/bin/aviator_bus --config config/system.yaml
./build/bin/manipulator --config config/system.yaml
./build/bin/aviator_core --config config/system.yaml --demo
```

在线目标示例使用 --servo-demo；交互模式不带 Demo 选项。仿真窗口属于 manipulator，--headless 可关闭；默认根 config/robot.yaml 为 mujoco。新节点不读取 build/bin/config，构建新 target 不触发旧示例的 aviator_assets 覆盖。

完整构建需要 AVIATOR_BUILD_ROBOTICS_LIBS=ON；AVIATOR_BUILD_MUJOCO、AVIATOR_BUILD_XCORE_SDK、AVIATOR_BUILD_VIEWER 分别控制设备后端与窗口。AVIATOR_COMMUNICATION_ONLY 不构建这两个运动节点，仍保留原通信构建范围。Bus 新增读取 YAML 配置，纯通信构建也需 libyaml-cpp-dev。

```bash
cmake --build build --target aviator_control_nodes_test aviator_motion_protocol_test
ctest --test-dir build -R '^(motion_protocol|control_nodes_.*)$' --output-on-failure
```

跨进程测试创建临时回环端口和独立配置，强制 MuJoCo；Demo 回归提高的是临时仿真配置的轮盘速度，不修改部署配置。测试输出目录在 /tmp/aviator-control-test-*。全程不连接真实机器人。

安装节点到 bin，配置与双臂模型到 share/aviator/config、share/aviator/models/control，SDK DSO 到 lib。通信数据用墙钟 CLOCK_MONOTONIC，跨进程仿真按实时节拍运行，不复用旧示例的无头加速时钟。
