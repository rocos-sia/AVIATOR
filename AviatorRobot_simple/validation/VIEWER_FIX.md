# 带窗口运动速度与相机交互修复

日期：2026-09-21；Ubuntu 22.04 x86_64，Release，实际 DISPLAY 窗口。

## 原因与修改

接近轨迹已有规划及插值，异常出在仿真节拍。物理线程的实时等待与
`waitTick()` 共用条件变量；后者消费节拍后的 `notify_all()` 提前结束了
无谓词的 `wait_until()`，物理线程未等到时间期限就继续步进。
控制算法使用仿真时间，因此整段规划被加速播放，看起来像跳到抓握位置。

修复前，活跃控制循环推进 0.6 s 仿真只用 0.032852 s 实际时间（约 **18.26 倍**）。
修复后同一测试用 0.599180 s（约 **1.00 倍**；起始一个节拍带来约 1 ms 边界差）。

修改 `DataLink_direct.cpp`：实时等待只允许模式切换或退出打断，普通节拍通知不能
提前推进；节拍间隔取模型 timestep，避免非 1 ms 模型被错误加速。
锁步切回实时也能在没有控制命令时自行恢复。无头演示仍保留加速模式。
未改短/改长接近轨迹，也未通过降低关节速度掩盖节拍问题。

原窗口未注册鼠标回调。现将 Viewer 提取到独立实现，采用随项目附带的
MuJoCo `sample/basic.cc` 相机映射，注册鼠标按键、移动、滚轮、键盘和失焦回调。
窗口首次渲染后才启动演示线程；相机操作不修改机器人或物理状态。

## 操作

- 左键拖动：旋转。
- 右键拖动：平移。
- Shift + 左/右键拖动：切换旋转/平移方向。
- 滚轮或中键拖动：缩放。
- R：恢复初始视角。
- Esc：停止任务并关闭窗口。

## 验证

| 项目 | 结果 |
|---|---|
| 修复前节拍回归 | 成功复现约 18 倍加速，测试失败 |
| 修复后节拍回归 | 活跃控制循环、实时/锁步切换、2 ms 模型均通过 |
| 默认 CTest | **8/8 通过**，80.96 s |
| 最后补充“锁步切回实时后无命令也恢复”检查 | 重新构建并单独重跑 `aviator_realtime` 通过 |
| 实际 GLFW 窗口回调测试 | 左键旋转、右键平移、滚轮/中键缩放、失焦释放、R 复位、Esc 退出通过 |
| 带窗口交互运动中 status / stop / quit | 通过 |
| 用户原命令 `./AviatorRobot_simple/build/bin/aviator --demo` | 完整执行成功，**93.40 s，退出码 0** |

完整演示时间包含模型初始化、轨迹规划、运动和驻留；“约 1 倍速”指物理时间推进，
不是要求程序总运行时间等于各运动时长之和。最后的模式切换补充只影响主动切换模式，
默认带窗口演示全程处于实时模式。
