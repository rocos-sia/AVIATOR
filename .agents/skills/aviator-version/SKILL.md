# AVIATOR 提交版本维护

从 Git 仓库根目录执行。先阅读 `docs/AVIATOR软件版本号规范.md`；涉及发布内容或测试校验码时，同时阅读 `docs/AVIATOR软件校验码规范.md` 和 `docs/AVIATOR版本与校验码实现方案.md`。

- 唯一版本源是根 `CMakeLists.txt` 的 `project(AVIATOR VERSION ...)`，不维护第二份版本常量，不提交 build/install 产物。
- 仅在用户要求创建 Git 提交时升级，查看实际待提交差异（包括配置、脚本、依赖、模型），以对外兼容性决定最高级别，不能按行数或提交标题判断。
- MAJOR：接口、命令、状态/故障语义、配置格式或控制安全契约不兼容；MINOR：向后兼容新增功能；PATCH：兼容修复及交付内容修订。按本项目每次提交维护版本的要求，纯文档、测试、工具维护也升 PATCH。提高高位时将低位归零。
- 新提交以 HEAD 中版本为基线；若待提交版本已正确升级，本次不再次递增。失败重试不重复升级。amend 保持该提交已分配版本，只有新增内容提升了兼容性级别时才相对父提交重新判断。
- 检查 MAJOR <= 255、MINOR <= 255、PATCH 为非负整数，十进制且无前导零。RS422 只编码 MAJOR/MINOR（高/低各 8 位）；PATCH 保留于完整版本和发布元数据，不占线上位。溢出时停止提交并说明原因，不自动进位掩盖语义，不截断或回绕。用户明确指定版本时优先遵从，同时检查规范合法性。
- 将版本修改与本次业务差异一起暂存。若根 CMakeLists.txt 还有不属于本次提交的编辑，仅暂存版本对应片段，保留其他编辑。不得把未授权的其他文件带入提交。
- 使用 `python3 tests/release_test.py` 验证版本/校验规则；在提交前说明版本变化及分类依据。提交后核对该提交包含正确版本。
- 本 skill 不创建发布标签、不推送、不自动发布。构建与安装计算内容摘要，但不递增版本。当前版本为 0.1.0 时，首次提交新增版本/校验功能应升至 0.2.0。
