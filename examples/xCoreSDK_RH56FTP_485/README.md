# xCoreSDK_RH56FTP_485

独立 C++17 / Qt5 双手测试程序，通过左右机械臂的 xCoreSDK 0.7.1.ar_10 末端 RS485 接口控制 RH56FTP。

当前版本保留机械臂电机上电。手部通信失败或执行器报错时，本侧暂停下发、保留连接和上电，继续间隔读取，等待手自行清错或通信恢复；正常侧继续轮询和接受本手命令。连接、上电等启动失败仍清理本侧；点击断开、关闭窗口或 Ctrl+C 停止双侧。不切换 RT/NRT 或手自动模式，不设置阻抗，不发送机械臂位置/速度/力矩目标，不启动机械臂状态流。末端供电沿用控制器当前设置，串口参数通过独立初始化流程写入；没有 `setxPanelRS485` / `setxPanelVout` 调用。

通信路径：`Qt UI → 每侧工作线程 → XPRS485SendData → 机械臂末端 RS485 → RH56FTP`。不使用 PC 串口或机械手网口。

## 正式握持逻辑测试 UI（新增）

`run_grip_demo.sh` 是独立的 Python/Tk 握持测试入口，复用正式 `xCoreSDK_hand` 的传输、
调度和整手暂停策略。它与下文原有 Qt 寄存器调试程序分开启动。

```bash
# 在仓库根目录构建共享 SDK 适配库（已有 build 配置）
cmake --build build --target aviator_xcore_hand_sdk -j4

# 真机：界面选择仅左手、仅右手或双手，再点击“连接”
./examples/xCoreSDK_RH56FTP_485/run_grip_demo.sh
# 默认选择右手
./examples/xCoreSDK_RH56FTP_485/run_grip_demo.sh --side right
# 离线模拟，无 SDK/机器人连接
./examples/xCoreSDK_RH56FTP_485/run_grip_demo.sh --fake-hand --side both
```

依赖 Python 3、tkinter、PyYAML；`UI_PYTHON` 可指定解释器。默认读取
`config/system.yaml` 中的 `core_hand.open/close`、手配置路径，以及 `robot.yaml` 的 SDK 地址。
可用 `--system-config` 和 `--sdk-library` 覆盖。未选中手不会连接、读取、写入或参与故障判断。
双手模式各自使用独立策略实例，单侧连接失败、设备故障不会阻断另一侧的按钮动作。

连接时张开所选手；点击“闭合”只提交一次闭合动作，由手节点自主读取反馈。
每只手六通道都满足配置的持续偏差或位置稳定判据后，向寄存器 1634 写一次 1 暂停。
不发 -1，不需要不断续发动作。界面显示实际位置、六通道判据和整手暂停状态；
点击“张开”恢复运动，再次点击“闭合”也会发起新动作。退出/断开会等待手安全张开写入完成。
故障码独立按 **50 ms / 20 Hz** 周期读取寄存器 1606 起的六个字节，正常读取不生成故障记录。
每次非零采样均写入故障日志（持续故障每次采样记录），界面显示最近 1000 条，恢复后历史仍保留。
记录包含北京时间（毫秒、UTC+08:00）、左右手、通道、十进制/十六进制故障码及中文说明：
堵转、过温、过流、电机异常、通信故障；组合位逐项展开，未知位保留原始十六进制值。
故障码读取失败单独记录为通信读取异常，不当作无故障。读取由设备线程执行，不依赖 UI 刷新，
短于界面刷新周期的已采样故障也会保留。故障码新采样不会被较慢的普通遥测覆盖。

故障日志默认保存到仓库 `logs/hand_grip_demo/<时间>-faults.log`，仅发生故障时创建。
界面底部显示路径；可用 `--log-file /absolute/path/faults.log` 指定。正常动作诊断仍显示在终端。
50 ms 是轮询调度周期，同一 RS485 端口串行；设备响应、SDK 超时或磁盘阻塞会使实际间隔延长，
不会补发积压查询。此频率覆盖仅左手、仅右手或双手中的所选手，不改变正式启动节点的默认频率。

切换测试范围前先断开。断开停止所选手读写；SDK 连接按正式节点的进程生命周期保留，
重新连接复用已成功建立的 SDK 连接，进程退出后回收。控制器 RS485 参数须已配置，末端须已有供电。
此入口只连接并收发手部 RS485，不上/下电、不切换机械臂模式、不发机械臂运动指令。
使用独立连接测试，勿与正式手节点或原 Qt 调试器同时写同一只手。

```bash
python3 examples/xCoreSDK_RH56FTP_485/test_grip_demo.py
```

## 独立构建与启动

需要 Linux x86_64、CMake ≥ 3.16、C++17 编译器、Qt5 Widgets（Ubuntu 的 `qtbase5-dev`），以及仓库内 SDK 的 `libxCoreSDK.a`、`libxMateModel.a`。不依赖 AVIATOR 主工程、ROS 或 Python。

```bash
cmake -S examples/xCoreSDK_RH56FTP_485 \
      -B examples/xCoreSDK_RH56FTP_485/build \
      -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build examples/xCoreSDK_RH56FTP_485/build -j4
ctest --test-dir examples/xCoreSDK_RH56FTP_485/build --output-on-failure

# 离线演示：不连接设备
./examples/xCoreSDK_RH56FTP_485/run.sh --offline

# 真机界面：点击“连接双手（电机上电）”才连接和上电
./examples/xCoreSDK_RH56FTP_485/run.sh \
  --config examples/xCoreSDK_RH56FTP_485/config.ini
```

启动脚本直接启动 UI，无需 sudo、CAP_SYS_NICE 或实时调度权限，`--check-rt` 已移除。SDK 位于其他目录时可设置 `-DXCORE_SDK_ROOT=/path/to/xCoreSDK-0.7.1`。

开始测试前，机械臂应处于静止状态，并关闭其他机器人控制客户端。程序沿用当前手自动模式；如果当前模式、急停或使能状态不允许上电，`setPowerState(true)` 将报错，程序不会自动更改模式或解除急停。

## 首次配置 RS485（重启后生效）

所有机器人实例使用 AR 专用 `rokae::ArRobot`，与已验证的 `xCoreSDK_hand_minimal` 一致。接收缓冲区按预期长度预分配，再把收发缓冲区的 `.size()` 传给 SDK。

本地 SDK 整包来源为 `librokae-v0.7.1.ar_10`，头文件和库已同步替换，目录名仍保留 `third_party/xCoreSDK-0.7.1`。

UI 勾选“仅初始化双侧 485”，点击“初始化双侧 485（不上电）”：每侧执行构造 → 连接 → 查询设备信息 → `xPanelRS485Init(baud115200, none, stopbit1, ec)` → `setxPanelRS485Overtime(500, ec)` → 断开。此流程不调用电机上电或手部读写。成功后按日志分别确认左右侧结果，**重启控制器**，再取消勾选并启动正常手部测试。单侧初始化失败不会取消另一侧的初始化，须按日志分别核对两侧结果。

也可以使用无界面的诊断入口（开始时电机应下电且机械臂静止）：

```bash
# 查看初始化计划，不连接设备
./examples/xCoreSDK_RH56FTP_485/build/rh56_485_probe --init-485 --dry-run
# 初始化两侧，或附加 --side left / --side right
./examples/xCoreSDK_RH56FTP_485/build/rh56_485_probe --init-485
```

[官方 AR 文档](https://docs.rokae.com/docs/SDK--0-7-x-AR/cpp/cpp_method/#xpanelrs485init) 明确说明串口参数设置后需要重启生效；程序不自动重启设备，也不将初始化成功当作手部通信成功。普通收发沿用控制器当前参数和超时，不重复设置。超时设置请求在初始化分支执行；程序不读回或保证重启后的超时值。`--init-485` 不能和 `--power-on` 同用。

## UI 正常会话的 SDK 调用顺序

左右侧分别执行以下顺序。SDK 对象的首次构造和连接共用互斥锁，以避开 0.7.1 全局日志器并发初始化问题；连接后两侧工作线程独立运行，不保证哪侧先完成。

1. 构造 `rokae::ArRobot()`。
2. `connectToRobot(robotIp)`：只传机器人 IP，不传本机 RT IP。
3. `robotInfo(ec)`、成功时 `sdkVersion()`：仅用于记录型号、控制器和 SDK 版本。
4. 沿用控制器当前 485 参数和超时，调用 **`setPowerState(true, ec)`**：保留电机上电；失败则进入清理。成功返回不等于末端电压已经测量确认。
5. 使用 **`XPRS485SendData(int(tx.size()), int(rx.size()), tx, rx, ec)`** 初始化读取手部：实际角度 → 实际受力 → 实际电流 → 执行器错误码 → 速度设置 → 力阈值设置。每只手读取成功且无执行器故障后，独立启用本手下发和读取按钮；只有两侧均就绪才启用“双手下发”。
6. 每轮反馈完成后等待 `poll_ms`，再通过同一接口读取实际角度 → 实际受力 → 实际电流 → 执行器错误码。
7. 用户点击下发时，通过同一接口依次写 **速度 → 力阈值 → 角度**，逐帧检查应答，然后重新读取第 5 步的六类数据。点击“立即读取”只执行第 6 步。
8. 手部收发失败（包括启动时首次读取）、应答校验失败或执行器错误码非零时，只拒绝并清空本侧命令，进入“等待恢复（自动读取中）”。每次读取结束或失败后等待 `poll_ms`，再次完整读取第 5 步的六类数据；持续失败不会自动下电或断开，也不主动发送清错指令。完整读取成功且六通道错误码全部为零后清除当前错误、恢复本侧按钮，旧命令不重放，需要重新点击下发。正常侧保持原有电机状态和手部控制。连接、上电等启动失败进入本侧清理；停止、关闭窗口或 SIGINT/SIGTERM 时清理双侧。清理对已尝试上电的连接调用 **`setPowerState(false, ec)`**，然后 **`disconnectFromRobot(ec)`**。下电失败仍尝试断开，并明确报告错误。

源码入口：`src/backend.cpp` 的 `Backend::Impl::run()`；构造和连接封装在 `src/sdk_robot.hpp`；帧编码在 `src/protocol.hpp`。

停止不发送手部张开命令，不切断末端电源。SDK 文档说明断开连接可能停止机器人运动，因此应在机械臂静止、无其他运动控制任务时使用本程序。

## 配置与界面

`config.ini` 只使用以下字段：

```ini
[left]
robot_ip=192.168.1.160
hand_id=1
[right]
robot_ip=192.168.2.160
hand_id=1
[control]
poll_ms=500
```

两只手位于不同总线，可以同为 ID=1。手 ID 范围 1～254，轮询间隔 100～10000 ms。旧配置中的 `local_ip`、`power`、`stiffness`、`rt_priority` 均被忽略。默认读取可执行文件旁的配置，`--config` 相对路径按启动目录解析；UI 修改只用于本次会话。

每手六通道：小指、无名指、中指、食指、拇指弯曲、拇指旋转。角度输入 0～1000 为协议归一化刻度，速度 0～1000，力阈值 0～3000。初次读取后用实测角度填入目标，速度输入默认 200、力阈值默认 300，点击下发才生效。“填入伸展/握合”仅修改前五通道，保留拇指旋转。

“双手下发各自参数”要求两侧均就绪，并将左右面板各自的参数入队，两条物理链路独立执行。若提交时任一侧未就绪，整次双手请求被拒绝，不会只向正常侧入队；已接纳的命令不保证双侧同时执行，单侧后续失败也不会撤销正常侧已执行的命令。每侧队列上限 8 条。单侧连接、通信、执行器或清理故障不会停止另一侧；故障侧按钮禁用，正常侧可继续通过“下发本手参数”和“立即读取本手反馈”操作。通信和执行器错误由后台自动轮询等待恢复，恢复后按钮自动启用；连接或上电失败后的重连仍需点击断开，等待全部清理后重新连接。UI 显示每侧错误、手反馈年龄、最近 485 耗时和原始帧。

同步 SDK 收发没有公开取消接口。超过 3 秒时本侧进入等待恢复，拒绝新命令并清空队列，等当前调用返回后再间隔读取，不并发发起另一笔收发；另一侧可继续操作。手反馈过期也进入等待恢复，阈值为 `max(3000, 2*poll_ms)` ms。用户点击停止后仍须等待正在执行的 SDK 调用返回才能下电和断开。

## 协议与串口

协议依据 `third_party/RH56FTP/C++/control_485.cpp` 及随附 RH56E2 手册：请求帧头 `EB 90`、响应 `90 EB`，读 `0x11`、写 `0x12`，校验为从 ID 到数据末尾的累加和低八位。实际 RH56FTP 固件兼容性仍需实测。

| 数据 | 字节地址 | 格式 |
| --- | --- | --- |
| 角度设置 | 1486 | 六个 little-endian 16-bit 值 |
| 力阈值设置 | 1498 | 六个 little-endian 16-bit 值 |
| 速度设置 | 1522 | 六个 little-endian 16-bit 值 |
| 实际角度 | 1546 | 六个 little-endian 16-bit 值 |
| 实际受力 | 1582 | 六个有符号 little-endian 16-bit 值，单位 g |
| 实际电流 | 1594 | 六个有符号 little-endian 16-bit 值，单位 mA |
| 执行器错误码 | 1606 | 六个单字节值 |

当前使用 AR_10 已在真机日志确认的 64 字节收发容量（头文件仍有 0～16 字节的旧注释）。角度、速度、力阈值、受力和电流均一次操作六通道，不拆分或偏移寄存器地址：读发送 9 字节、接收 20 字节；写发送 20 字节、接收 9 字节。六个单字节错误码仍一次读取，发送 9 字节、接收 14 字节。初始化读取共 6 次 SDK 收发，普通轮询共 4 次，参数下发共 3 次，随后完整读取共 6 次。

“一帧六通道”指同类寄存器的六个值；速度、力阈值和角度仍分三次写入。每帧检查长度、帧头、ID、操作码、地址、校验和及写确认值 1。多类参数之间不具备原子性，后续写入失败时此前写入可能已生效；报错后取消剩余写入，不自动重发。恢复轮询会读回速度和力阈值等状态，但不会自动补发之前的角度目标。

手部示例使用 **115200 / 8N1**，应核实控制器末端实际配置与手一致。本地 SDK 已替换为 AR 专用 `0.7.1.ar_10`；使用上述初始化入口设置控制器侧串口参数，不写手部 Flash。[官方 AR 文档](https://docs.rokae.com/docs/SDK--0-7-x-AR/cpp/cpp_method/#setxpanelrs485) 说明 AR 默认输出 24V 并开启 RS485，无需调用 `setxPanelRS485`。

## 日志与只读诊断

每次运行在 `~/.local/share/xCoreSDK_RH56FTP_485/sessions/run-XXXXXX/` 创建独立目录（遵循 `XDG_DATA_HOME`），保存 `session.log`、SDK `logs/` 和 `_rokae_log_/`，退出后保留。原始帧始终写入日志，UI 复选框仅控制显示。SDK 失败时 RX 只是缓冲内容，不代表有效应答。

### 左右手 CSV 自动记录

通过 `run.sh` 启动后，CSV 默认保存到 `/home/rocos/Documents/hand_csv`，每次运行使用独立的 `run-XXXXXX` 子目录（与 SDK 运行目录同名），连接时自动创建目录及 `left_hand.csv`、`right_hand.csv`，无需额外参数或点击保存。终端和界面日志显示完整 CSV 保存路径；SDK 日志和 `session.log` 仍保存在上述原运行目录。默认路径为：

```text
/home/rocos/Documents/hand_csv/run-XXXXXX/left_hand.csv
/home/rocos/Documents/hand_csv/run-XXXXXX/right_hand.csv
```

每侧完成一次有效反馈读取后追加一行并刷新文件，包括首次读取、定时轮询、手动读取、下发后的读取及恢复读取。普通轮询的间隔为本轮读取耗时加 `poll_ms`，不是固定采样频率；两侧独立采样，多类寄存器依次读取，不代表同一瞬间的测量。通信失败、帧校验失败或数据校验失败的轮次不写入，避免旧数据冒充新反馈；完整读到非零执行器错误码时仍记录，并通过错误码列标识。

CSV 使用英文表头，共 46 列：

| 列 | 含义 |
| --- | --- |
| `timestamp_utc` | 完成本轮反馈时的 UTC 时间，含毫秒，末尾 `Z`；北京时间为 UTC+8 |
| `connection_id` | 本次程序运行中的连接编号，重连后递增 |
| `elapsed_ms` | 本次连接开始记录以来的单调时钟毫秒数 |
| `offline` | `0` 为设备通信模式，`1` 为离线模拟数据 |
| `<channel>_target_position_raw` | 最近收到成功应答的下发位置，协议角度刻度 0～1000 |
| `<channel>_configured_force_g` | 最近完整读取确认的设备力阈值设置，单位 g |
| `<channel>_configured_speed_raw` | 最近完整读取确认的设备速度设置，协议刻度 0～1000 |
| `<channel>_actual_position_raw` | 实际位置，沿用界面的协议角度刻度 0～1000 |
| `<channel>_actual_force_g` | 实际受力，保留有符号值，单位 g |
| `<channel>_actual_current_mA` | 实际电流，保留有符号值，单位 mA |
| `<channel>_error_code` | 执行器原始错误码，0 表示无错误 |

每个通道依次包含表中的七项数据，通道顺序为 `little`（小指）、`ring`（无名指）、`middle`（中指）、`index`（食指）、`thumb_flex`（拇指弯曲）、`thumb_rotation`（拇指旋转）。位置不是角度单位“度”或执行器行程，速度不是实际测速；力的 g 单位沿用厂商指尖握力定义，未换算为 N。电流地址和单位依据随附手册第 2.6.17 节，符号处理与厂商 ROS C++ 示例及主工程节点一致。

界面尚未下发的输入不会进入 CSV。首次下发前目标位置留空，速度和力阈值来自设备初次读回；后续下发或恢复时重新读取设置，因此部分写入已生效时会记录设备实际配置。位置写入应答丢失时，目标列留空，直到下一次位置下发得到成功应答；实际位置仍按设备反馈记录，不能据此推定原目标。记录的是反馈采样对应的最近目标，不是每条排队命令的独立事件日志。

同一窗口断开再连接会追加到原文件，表头只写一次，目标位置重新从空值开始；重新启动程序会创建新的运行目录。`--offline` 也生成 CSV，模拟力和电流为 0，并标记 `offline=1`；仅初始化 485 时不创建 CSV。打开或写入 CSV 失败会在界面及 `session.log` 明确报告，并停止本侧此次连接的记录，手部通信仍继续，另一侧记录不受影响；重连时重新尝试打开文件。每行刷新到操作系统，不保证断电时物理磁盘已完成落盘。

独立 `rh56_485_probe` 按左、右顺序，默认用原厂完整请求一次读取六通道角度（发送 9 字节、接收 20 字节）；`--full-angle` 保留为兼容选项，`--three-angle` 用于旧三通道请求的对照。开始前检查电机下电且机械臂静止；默认不改变电机状态，`--power-on` 则在当前模式上电、读回确认、等待 2 秒后读取，结束请求并确认下电。该诊断也不切换任何控制模式，不设置阻抗或 xPanel；失败时额外查询最近控制器日志。

```bash
./examples/xCoreSDK_RH56FTP_485/build/rh56_485_probe --dry-run
./examples/xCoreSDK_RH56FTP_485/build/rh56_485_probe --side left
./examples/xCoreSDK_RH56FTP_485/build/rh56_485_probe --power-on
```

## 验证范围

`hand_csv_recording` 检查双手六通道数据、时间与单位表头、有符号电流、读取失败不写旧值、部分下发与应答丢失、重连追加、离线标记及文件错误隔离；`rh56_protocol` 检查六通道固定帧、电流读取地址及符号解码、每次读写只有一次传输、校验、异常应答和失败不重试；`dual_hand_offline` 检查双手就绪门控、独立参数、停止/重连、旧配置兼容及 Qt 操作；`hand_failure_isolation` 将实际后端/UI 源码与测试专用 SDK 替身编译，模拟单侧上电失败、首次读取失败、持续通信失败超过 3 秒、执行器自动清错、校验失败、SDK 阻塞后恢复、写入已执行但应答丢失及下电失败，检查恢复期间持续轮询、不下电不断开、正常侧读写、故障侧队列丢弃、双手请求拒绝、恢复后按钮启用、部分写入读回且不重放和停止/重连；`sdk_runtime_logging` 检查不可写启动目录下的 SDK 日志隔离；`sdk_concurrent_startup` 检查实际 SDK 对象的并发构造保护。测试不连接或上电真机，不能证明实际 485 通信已恢复。
