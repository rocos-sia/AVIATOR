# aviator-icd-1120 帧布局 / ICD 1127 状态与故障语义

本文件是独立模拟器使用的协议快照：帧布局及物理单位沿用 ICD 1120，状态及故障语义按《【公开】ICD文件-1127.docx》和《AVIATOR故障编码规范》1127 修订（56 个故障码）执行。两路全双工串口固定 115200 / 8E1，80 Hz。多字节数值为小端；帧计数器每周期加一，按 256 回绕。两路下行的同一周期使用相同计数器和数据。

机器人网关的状态生成逻辑须另行完成 1127 适配。本模拟器不将旧网关的 `FE/FFFF/FF` 反馈改写为正常或告警；这类不符合新约定的报文会拒收且不刷新接收时效。

本次布局为 32/64 字节，上下行均无帧尾，不兼容旧 9/29 字节实现。profile 名称保持不变，两端必须配套更新；不自动识别旧帧。

位置采用 int16 小端补码，滚转 `raw×50/32767` deg，俯仰 `raw×75/32767−5` mm。
下行、回绕和两路反馈均为滚转 ±50°、俯仰 −80～+70 mm；有效编码 −32767～32767。
−32768（`00 80`）为无效位置，下行拒收，上行逐轴使用。反馈越界标无效，不截断。
俯仰物理零位的编码为 2184，原始值 0 表示 −5 mm。左正右负、推正拉负。

位置字段表示绝对角度/位移，不再表示百分比；也不是相邻帧的增量。编码如下：

| 自由度 | 物理范围 | 发送编码（四舍五入，半单位远离零） | 分辨率 |
| --- | --- | --- | --- |
| 滚转 | −50°～+50° | `round(roll_deg × 32767 / 50)` | `50/32767 ≈ 0.001526°/LSB` |
| 俯仰 | −80～+70 mm | `round((pitch_mm + 5) × 32767 / 75)` | `75/32767 ≈ 0.002289 mm/LSB` |

同一换算适用于下行目标、上行目标回绕、相机反馈和关节 FK 反馈。摇杆先转换为物理目标：中位是 0° / 0 mm，左右满量程为 +50° / −50°，前推/后拉满量程为 +70 / −80 mm；俯仰两侧行程不对称。键盘按 deg/s、mm/s 积分得到绝对目标，松键后保持该目标。

## 下行：B 飞控模拟器 → A 机器人（32 字节）

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 2 | 帧头 EB 90 |
| 2 | 1 | 周期计数器 |
| 3 | 1 | 操作，00 空闲、10 待命、20 握盘、30 开始控制、40 退出控制、50 松盘、60 复位错误（十六进制） |
| 4 | 2 | roll 目标 |
| 6 | 2 | pitch 目标 |
| 8～30 | 23 | 备用位，发送填零，接收忽略业务含义但参与校验 |
| 31 | 1 | 校验 = 字节 2～30 累加，模 256（不含帧头） |

零计数、空闲、物理零目标（0°、0 mm）固定向量：`EB 90 00 00 00 00 88 08` + 23 个 `00` + `90`（共 32 字节）。俯仰编码 `0x0888 = 2184`，量化后约为 −0.001068 mm。
`EB 90` + 30 个 `00` 也是有效帧，但其俯仰目标为 −5 mm，不能用作物理归零指令。

一次按钮操作连续发送 10 拍，无启动或操作后的 10 拍空闲等待。不同操作码可以直接衔接；同一操作码的两次紧邻点击自动插入一帧 `0x00` 作为分隔。无操作时发送 `0x00`，操作发送期间不排队。输入无效即停发；串口重连或调度跳拍时取消未完成操作，回到 `0x00`，不自动重发。A 端负责通道健康检查、连续 5 拍且至少 50 ms 的操作确认、同一段操作码只派发一次，以及状态机授权。

| 状态码（十六进制） | 状态 |
| --- | --- |
| 01 / 03 | INIT / READY |
| 05 / 07 / 08 | STANDBY / FOLLOWING / CONTROL |
| 09 | 保留，原 SAFE 已退役，不发送 |
| 10 / 11 / 12 / 13 / 14 | ERROR / INITIALIZING / HOMING / GRASPING / RELEASING |
| FE | NOT_STARTED，未启动，正常启动等待；当前故障码及故障状态均为 0 |
| FF | EMERGENCY_STOP，急停锁存 |

状态字段 `0x00` 未分配，当前接收端拒绝该值；不能按旧表将其解释为急停。未启动 `0xFE` 与急停 `0xFF` 严格区分。不支持的状态名称不能编码为未启动。

软件版本按 `(MAJOR << 8) | MINOR` 编码，完整发布版本的 PATCH 不上串口。8E1 每个 UART 字共 11 位；帧校验不取补码。

版本编码与短码由 A 端生成，B 端以四位十六进制原样显示，不参与生成机器人发布身份。接收端严格检查帧头、长度、校验和字段范围；只接受协议中已分配的 56 个业务故障码或 0。新鲜窗口内重复或倒退计数帧不续期。默认连续 50 ms 未收到有效新上行显示 STALE。

未启动 `FE` 是收到的机器人运行状态，模拟器尚未收到有效帧时只显示 `WAITING`，不伪造机器人正常或未启动。状态 14 继续表示释放中；位置 -32768、选中通道/后退/手刹的 FF 仍保留原有无效或未接入含义，但故障字段不使用未知标记。串口无 LEN、事务 ID、额外 ACK 或 ZMQ 封装；操作回绕不等同于业务完成。

## ICD 1127 故障语义

未启动是正常等待：字节 10 为 `FE`，字节 17～18 为 `00 00`，字节 21 为 `00`，不需要告警确认或复位。`7201` 未分配，不发送、不接受。

| 新增故障码（十进制） | 含义 | 字节 21 |
| --- | --- | --- |
| 7202 | Core 状态反馈超时 | `30` 告警 |
| 7203 | Core 状态数据明确无效 | `30` 告警 |
| 7204 | Core 状态报文格式错误 | `30` 告警 |
| 7205 | Core 运行状态值不支持 | `30` 告警 |
| 7206 | Core 状态时间基准异常 | `30` 告警 |
| 8212 | Core 诊断编码异常 | `30` 告警 |

原有 50 个业务故障码保持不变。当前故障为 0 时故障状态必须为 00，否则由 CSNN 的 S 位映射为 10/20/30/40；历史故障不参与当前等级计算。已确认急停状态仍上报 FF，不因当前诊断编码异常隐藏急停。模拟器不会根据本机串口超时合成机器人 ERROR：接收过期只标记 STALE，并保留最后有效帧。

网关历史字段从 0 开始；当前故障由非零 A 切换为其他值时锁存 A，同码重复上报不覆盖历史，普通复位不清空历史，网关重启后重新从 0 开始。模拟器按接收值显示，不代替网关生成历史。

状态反馈恢复可恢复实际运行状态；告警原因消除后仍按需手动恢复规则确认清除。模拟器只发送既有复位指令，不新增自动确认、自动复位或自动恢复操控行为；人工确认与网关/Core 的衔接以机器人端实现为准。
