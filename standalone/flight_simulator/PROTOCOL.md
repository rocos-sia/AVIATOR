# aviator-bench-v1 线协议

本文件是独立模拟器使用的协议快照，对应 AVIATOR《RS422 通信协议规范》第 10 节台架扩展约定。两路全双工串口固定 115200 / 8E1，80 Hz。多字节数值为小端；帧计数器每周期加一，按 256 回绕。两路下行的同一周期使用相同计数器和数据。

本次布局为 32/64 字节，上下行均无帧尾，不兼容旧 9/29 字节实现。profile 名称保持不变，两端必须配套更新；不自动识别旧帧。

位置采用有符号 int16，数值 1000 表示 100%，即 0.1 个百分点/LSB。下行允许 ±1000；实测 roll/pitch 上行允许 ±1040/±1059。未知位置为 -32768（线字节 `00 80`）。

## 下行：B 飞控模拟器 → A 机器人（32 字节）

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 2 | 帧头 EB 90 |
| 2 | 1 | 周期计数器 |
| 3 | 1 | 操作，00 空闲、10 待命、20 握盘、30 开始控制、40 退出控制、50 松盘、60 复位错误（十六进制） |
| 4 | 2 | roll 目标 |
| 6 | 2 | pitch 目标 |
| 8～30 | 23 | 备用位，发送填零，接收忽略业务含义但参与校验 |
| 31 | 1 | 校验 = 字节 2～30 累加，模 256（不含帧头） |

零计数、空闲、零目标固定向量：`EB 90` + 29 个 `00` + `00`（共 32 字节）。

启动至少 10 拍空闲；一次按钮操作连续 10 拍，再至少 10 拍空闲。操作期间不排队。输入无效即停发；串口重连或调度跳拍时取消未完成操作，重新进入空闲序列。A 端负责通道健康检查、双路去重和状态机授权。

## 上行：A 机器人 → B 飞控模拟器（64 字节）

| 偏移 | 长度 | 含义 |
| --- | --- | --- |
| 0 | 2 | EB 90 |
| 2 | 1 | 周期计数器 |
| 3 | 1 | 选中通道：0=A、1=B、FF=未知 |
| 4 | 1 | 通信异常位：bit0=A、bit1=B；0=均正常 |
| 5 | 1 | 操作回绕 |
| 6 | 2 | roll 目标回绕 |
| 8 | 2 | pitch 目标回绕 |
| 10 | 1 | 机器人状态，见下表 |
| 11 | 1 | 后退到位，0/1/FF未知 |
| 12 | 1 | 手刹状态，0/1/FF未知 |
| 13 | 2 | roll 实测位置 |
| 15 | 2 | pitch 实测位置 |
| 17 | 2 | 当前故障：0=无故障，FFFF=未知 |
| 19 | 2 | 历史故障：0=无故障，FFFF=未知 |
| 21 | 1 | 故障等级：00/10/20/30/40，FF未知 |
| 22 | 2 | 软件版本：字节 22 为小版本，字节 23 为主版本，各 0～255；2.01 → 01 02 |
| 24 | 2 | 软件短校验码 |
| 26～62 | 37 | 备用位，发送填零，接收忽略业务含义但参与校验 |
| 63 | 1 | 校验 = 字节 2～62 累加，模 256（不含帧头）；无帧尾 |

| 状态码（十六进制） | 状态 |
| --- | --- |
| 00 / 01 / 03 | EMERGENCY_STOP / INIT / READY |
| 05 / 07 / 08 | STANDBY / FOLLOWING / CONTROL |
| 09 | 保留，原 SAFE 已退役，不发送 |
| 10 / 11 / 12 / 13 / 14 | ERROR / INITIALIZING / HOMING / GRASPING / RELEASING |
| FF | UNKNOWN |

软件版本按 `(MAJOR << 8) | MINOR` 编码，完整发布版本的 PATCH 不上串口。8E1 每个 UART 字共 11 位；帧校验不取补码。

版本编码与短码由 A 端生成，B 端以四位十六进制原样显示，不参与生成机器人发布身份。接收端严格检查帧头、长度、校验和字段范围；只接受协议中已分配的 50 个业务故障码、0 或 FFFF。新鲜窗口内重复或倒退计数帧不续期。默认连续 50 ms 未收到有效新上行显示 STALE。

本台架使用 FF、FFFF、-32768 和状态 14 等扩展值表达未接入的反馈和释放中状态。双方必须显式选择此 profile；不能把未知值当作零或正常。串口无 LEN、事务 ID、额外 ACK 或 ZMQ 封装；操作回绕不等同于业务完成。
