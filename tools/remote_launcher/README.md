# AVIATOR 远程启动界面

独立控制端，支持 Ubuntu 22.04 / 24.04 桌面。控制机不需要 AVIATOR 源码、C++ 编译环境或相机 SDK。
工控机继续执行已部署的 `/opt/aviator/share/aviator/scripts/start_aviator.sh`。

## 在另一台控制机使用

将 `aviator-remote-ui.tar.gz` 复制到控制机，然后：

```bash
tar -xzf aviator-remote-ui.tar.gz
cd aviator-remote-ui
./install_dependencies.sh  # 新控制机首次使用，安装 Tk、SSH 客户端、rsync
./start.sh
```

依赖已安装时可以跳过安装步骤；依赖安装需要该控制机自己的 sudo 密码。键盘窗口转发还需要 `xauth`（已包含在安装脚本中）。
启动不需要 sudo。控制机必须能通过网络访问 `192.168.11.100:22`，并有可用的桌面环境。
固定连接用户 `rocos`、工控机地址和 SSH 密码放在 `tools/remote_launcher/connection.json`，需要认证时自动填写。
包内包含连接凭据，请仅分发给可信控制机；不包含机器人 C++ 源码和现场配置。
首次 SSH 连接自动记住主机密钥；已知主机密钥发生变化时仍会拒绝连接。

在源码目录直接运行 `./scripts/start_remote_aviator.sh`。
重新打包：`python3 scripts/package_remote_launcher.py`，输出在 `build/remote-launcher/`。

## 操作

1. 默认使用真实机械臂和真实手。按需选择 `--rs422`（小写）、`--fake-hand`、`--tts`。
   每次打开界面时模拟手都默认为关闭；其他选项记住上次选择。
   首次打开默认勾选“本机键盘控制”；选择 RS422 时自动取消并禁用键盘选项。
2. 可启用记录数据 `--logger`；再选择是否同时回传，以及本机保存目录。
3. 点击“启动工控机”。界面显示启动日志，并持续显示带节点名称的 warning/error/critical 日志；全部节点及 Monitor 就绪后，在本机自动打开
   `http://127.0.0.1:8081/`。SSH 隧道只绑定本机回环地址，端口占用时会在启动设备前报错。
4. 点击“停止并收尾”，按原脚本顺序停止设备并完成记录写盘。关闭界面也会请求停止，等收尾和补传结束后退出。

## 本机键盘控制

勾选“本机键盘控制”后，SSH X11 转发把工控机上原有的 `flight_gateway / 输入操作指南` 窗口显示到本机。
**先点击该输入窗口取得焦点，再按键；在 Monitor 浏览器或启动界面按键不会控制动作。**
Monitor 自动打开时可能取得焦点，需重新点击输入窗口。

- 左/右：roll 减/加；上/下：pitch 减/加。按住累加，松开或到限位保持；`0` 回到目标原点。
- 数字键、减号和小键盘沿用现场 `flight.yaml` 的按钮映射，以输入窗口显示的说明为准。
- 原逻辑保持不变：失焦立即停止键盘目标累加、保持已有目标；仅用键盘时失焦满 5 分钟，输入失效。
  关闭输入窗口会退出网关，原启动脚本随之停止整组节点。不是任意机械臂关节的点动控制，仍受原 Core 状态限制。
- `--rs422` 使用独立输入来源，不与本机键盘同时启用。取消键盘选项时，仍可使用连接工控机的摇杆。
- 键盘会话对固定的可信工控机使用 SSH `-Y`，避免非信任转发下 SDL 窗口存活回复丢失、桌面反复提示“无响应”。
  此模式允许远端图形程序访问本机 X11 会话，仅用于可信工控机；不使用 `xhost +`。未启用键盘时关闭 X11 转发。
  控制机需有 X11/XWayland 桌面和 `xauth`，工控机需安装 `xauth`，SSH 服务允许 `X11Forwarding yes`。
  启动前检查显示链路，失败时不启动设备。重连收尾无需显示链路。

网关程序仍运行在工控机，沿用原来的键盘处理、速度、限位、失焦保护和设备启停顺序；没有新增另一套动作协议。
网络故障时仍按下面的看护超时请求正常停止，不能把窗口转发当作实时链路或急停按钮。
本机 USB 摇杆不会自动转发；RS422、相机及音频设备仍连接工控机，TTS 从工控机播放。
相机保持采集及 Monitor 预览，不弹出工控机相机窗口和 Chrome；不会修改现场 YAML/INI。

## 数据与断线

- 每次运行单独的 UUID 目录，工控机保存在 `~/.local/share/aviator-remote/recordings/<运行ID>/`。
  主 MCAP 和图像 MCAP 放在同一个目录；仅对本次远程运行覆盖输出路径，不写现场配置。
- 回传到所选本机目录下的相同运行 ID。每 5 秒尝试同步一次，带宽限制为 8 MiB/s；
  大体积图像可能产生积压，不保证实时无延迟。本机运行中的 MCAP 尚未完成，不能视为完整记录。
- 停止后重新校验文件内容并补齐，包括写盘时改写的文件头。成功后移除本机 `.in-progress` 标记。
  远端数据始终保留，不自动删除。启动失败也可能留下部分记录，完整回传不代表该次采集成功。
- 网络断开或本机进程退出后，工控机看护进程在连接关闭时或约 20 秒心跳超时后请求原启动脚本正常停止。
  这不是紧急停机机制；最终退出仍需要原有设备清理流程完成。
- 本机 SSH 隧道由界面直接管理：结束会话时取消 8081 转发并等待 SSH 进程退出后再删除连接文件。
  即使界面进程异常终止，SSH 主连接也会随之退出，避免残留占用本机端口。
- 网络恢复后点击“重连并收尾 / 补传”，确认并结束先前会话、补传记录。该按钮不会重新启动设备。
  会话信息存在本机 `~/.local/state/aviator-remote-ui/session.json`；保留该文件才能自动恢复。
  更换控制机前应先在原控制机完成停止和回传。
- 远端启动日志：`~/.local/state/aviator-remote/<运行ID>/launcher.log`，包含转发到界面的节点警告和错误；完整节点日志路径见其中输出。

## 工控机要求

工控机需要已部署支持 `AVIATOR_REMOTE_UI=1` / `AVIATOR_REMOTE_KEYBOARD=1` 的新版本启动脚本，以及 Python 3、SSH 服务、rsync 和 xauth。
旧脚本会在启动设备前被拒绝，请先用项目的一键部署脚本更新，现场配置仍按部署规则保留。
本工具不编译、不部署程序，也不会在打开界面时自动启动设备。
